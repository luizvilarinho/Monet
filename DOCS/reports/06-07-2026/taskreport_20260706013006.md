# Task: Fase 1 do Leitor de Livros — Biblioteca + Leitor de PDF básico

## Objective

Criar a fundação do leitor de livros do Monet: um novo modo "Library" no app com uma lista de livros (PDFs) que o usuário pode importar, e um leitor de PDF que abre ao selecionar um livro, com navegação de páginas, zoom e memória da última página lida. Esta é a Fase 1 da feature de leitura assistida por IA (visão em `DOCS/specs/productVision.md`): fases futuras adicionarão grifos, citações para cadernos e chat de IA com contexto de leitura — a Fase 1 deve deixar a estrutura pronta para isso.

## Context

- Novo modo de tela ao lado de Notebook e Chat: `ActiveMode` em `src/components/Toolbar/Toolbar.tsx` hoje é `'notebook' | 'chat'`; ganhará `'library'`, com roteamento em `src/App.tsx`.
- Renderização de PDF no front com `pdfjs-dist` (já presente em `package.json`, v5.6, ainda não utilizado) — renderização em canvas com text layer habilitada (a text layer é pré-requisito das fases futuras de seleção/grifo).
- Import de PDF via backend Tauri: `src-tauri/src/documents.rs` já tem file dialog com filtro PDF e extração de texto (`pdf_extract`) usada pela Knowledge Base.
- Persistência de metadados dos livros no SQLite (`monet.db`) seguindo o padrão existente da camada `src/storage/` (`tauri.ts` / `browser.ts` / `index.ts`).
- Novos componentes em `src/components/` (ex.: `Library/` para a lista e `Reader/` para o leitor), seguindo o padrão de CSS Modules do projeto.

## Requirements

- Novo botão "Library" na navegação de modos do Toolbar; o modo abre a tela da biblioteca.
- Tela de biblioteca com **tabela de livros**: título, autor (se disponível nos metadados do PDF; senão editável ou vazio), total de páginas, progresso de leitura (última página lida / total), data de adição e último acesso.
- Botão de importar livro: abre file dialog (somente `.pdf`), copia o arquivo para o diretório de dados do app (o livro não pode quebrar se o usuário mover/apagar o arquivo original) e registra o livro no banco.
- Nova tabela `books` no SQLite com, no mínimo: `id`, `title`, `author`, `file_path`, `total_pages`, `last_page`, `added_at`, `last_opened_at`. Título/autor extraídos dos metadados do PDF quando existirem, com fallback para o nome do arquivo.
- Clicar em um livro na tabela abre o **leitor**: renderização das páginas via pdfjs-dist com text layer, navegação (anterior/próxima, ir para página N, atalhos de teclado ←/→), controle de zoom e indicador "página X de Y".
- O leitor persiste a página atual do livro (`last_page`) e, ao reabrir o livro, retorna à última página lida. `last_opened_at` é atualizado ao abrir.
- Botão de voltar do leitor para a lista da biblioteca.
- Ações mínimas de gestão na tabela: remover livro (com confirmação — remove o registro e a cópia do arquivo) e renomear título/autor.
- UI em inglês, consistente com o restante do app (idioma migrado em 2026-05-17).

## Constraints

- Não implementar nesta fase: grifos, anotações, cópia de citações, chat de IA no leitor, indexação do livro na Knowledge Base. A Fase 1 é somente biblioteca + leitor. A estrutura, porém, não deve dificultar essas adições (ex.: text layer ativa desde já; IDs estáveis de livro).
- Reusar a infraestrutura existente: camada `src/storage/` para SQLite, file dialog do backend Tauri, padrão de componentes com CSS Modules. Não introduzir dependências novas de UI; `pdfjs-dist` já está no projeto.
- Worker do pdfjs configurado para funcionar no build Tauri (sem carregar worker de CDN — o app é desktop e deve funcionar offline).
- Seguir o padrão dev/prod de bancos separados (`npm run tauri:dev` usa `com.monet.app.dev`).
- Dead code encontrado no caminho da implementação deve ser removido, não deixado para depois.

## Edge Cases

- PDF escaneado (sem camada de texto): deve abrir e renderizar normalmente; a ausência de text layer não pode quebrar o leitor.
- PDF corrompido ou protegido por senha: o import deve falhar com mensagem clara, sem registrar livro órfão no banco.
- Import do mesmo arquivo duas vezes: decidir comportamento simples e explícito (permitir duplicata ou avisar) — não pode corromper registros.
- Arquivo do livro ausente no diretório do app (apagado manualmente): a biblioteca lista o livro, mas ao abrir mostra erro amigável em vez de tela quebrada.
- PDFs grandes (500+ páginas): renderizar sob demanda (página atual e vizinhas), não o documento inteiro de uma vez.
- `last_page` maior que `total_pages` (dados inconsistentes): clampar para o intervalo válido.
- Livro aberto quando o app é fechado: a última página deve ter sido persistida (salvar na troca de página, não apenas ao sair do leitor).
