## Escopo

Novo modo "Library" no app: tabela de livros PDF importados (título, autor, páginas, progresso, datas) com importar/remover/renomear, e leitor de PDF (pdfjs-dist 5.6, canvas + text layer) com navegação, zoom, indicador de página e memória da última página lida. Persistência na nova tabela `books` (Migration v12, propriedade do frontend via plugin-sql); arquivos copiados para `app_data_dir/books/` via 3 comandos Rust novos restritos a arquivos. Sem grifos, anotações, citações ou IA nesta fase.

## Decisões técnicas fixadas (não reabrir)

1. **Worker do pdfjs offline**: import `?url` do Vite (`pdfjs-dist/build/pdf.worker.min.mjs?url`) + `GlobalWorkerOptions.workerSrc`. Assets `wasm/`, `standard_fonts/` e `cmaps/` do pdfjs copiados para o bundle e apontados nas options do `getDocument`.
2. **Tabela `books`**: Migration v12 em `src-tauri/src/lib.rs`, propriedade EXCLUSIVA do frontend (plugin-sql). O Rust nunca toca essa tabela (invariante de dono único documentado no topo de `documents.rs`).
3. **Comandos Rust** (novo módulo `src-tauri/src/books.rs`), restritos a arquivo: `books_import_file` (dialog rfd só-PDF + cópia para `app_data_dir()/books/<uuid>.pdf`), `books_read_file` (bytes crus via `tauri::ipc::Response`), `books_delete_file`. Sem mudanças em CSP ou capabilities.
4. **Metadados** (Title/Author/numPages): extraídos no frontend via pdfjs durante o import — isso também valida PDF corrompido/com senha ANTES de inserir no banco; se a validação falhar, o front chama `books_delete_file` para desfazer a cópia (sem livro órfão).
5. **Import duplicado**: permitido — cada import gera UUID e cópia própria. Sem hashing na Fase 1.
6. **UI**: `ActiveMode` ganha `'library'`; roteamento em `App.tsx` (incluindo o parse de `monet:active-mode` no localStorage, que hoje descarta valores desconhecidos). Componentes novos com CSS Modules: `src/components/Library/` e `src/components/Reader/`. Referência de tabela: `KnowledgeBaseModal`.

## Avisos de API para o codeAgent (pdfjs 5.6 — exemplos antigos da web NÃO funcionam)

- `renderTextLayer` não existe mais. Usar a classe `TextLayer`:
  ```ts
  import { TextLayer } from 'pdfjs-dist'
  const tl = new TextLayer({ textContentSource: page.streamTextContent(), container, viewport })
  await tl.render()
  ```
- O container do text layer precisa da CSS var `--total-scale-factor` (não mais só `--scale-factor`): `container.style.setProperty('--total-scale-factor', String(viewport.scale))`.
- Não importar `pdfjs-dist/web/pdf_viewer.css` completo — escrever CSS mínimo próprio para o text layer (spans transparentes, `position: absolute`, `transform-origin: 0 0`, container `position: absolute; inset: 0; overflow: hidden; line-height: 1`).
- Erros de PDF inválido/senha: `getDocument(...).promise` rejeita com exceção cujo `.name` é `'InvalidPDFException'` ou `'PasswordException'` — usar `.name` para a mensagem de erro, não `instanceof`.
- Gestão de memória: cancelar `renderTask` pendente ao trocar de página (`renderTask.cancel()` — a rejeição com `RenderingCancelledException` deve ser engolida), `page.cleanup()` em páginas distantes, `doc.destroy()` ao desmontar o leitor.
