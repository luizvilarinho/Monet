## Achados

### 1. `[importante]` Reader: navegação "vai e volta" dentro do debounce persiste página errada

`src/components/Reader/Reader.tsx:178-186`. O effect de debounce retorna cedo quando `pageNum === bookRef.current.lastPage`, **sem limpar `pendingPageRef` nem o timer armado pela execução anterior**. Cenário: usuário na página 1 pressiona → e ← em menos de 500 ms. A ida (pageNum=2) agenda o timer com `pending=2`; a volta (pageNum=1 === lastPage) cai no early return e deixa o timer vivo → o flush grava `last_page = 2` no banco enquanto o usuário está na página 1. Se ele sair sem trocar de página de novo, o livro reabre na página errada. Viola o Requirement "ao reabrir o livro, retorna à última página lida" nessa interação.

Correção sugerida: no ramo de early return, limpar o timer e zerar `pendingPageRef` (ou remover o guard e deixar o save idempotente rodar).

### 2. `[importante]` Reader: render do TextLayer não é cancelado nem re-checa `cancelled` — race em navegação rápida

`src/components/Reader/Reader.tsx:124-148`. O `renderTask` do canvas é cancelado corretamente no cleanup, mas o `TextLayer.render()` (async, streaming) não: ao segurar →/← (key repeat), uma execução antiga do effect pode continuar despejando spans no **mesmo container** depois que a execução nova já fez `innerHTML = ''` e começou o text layer da página atual → text layer com spans de duas páginas misturados (seleção/posições erradas — e o text layer é a base das fases de grifo/citação). Além disso, após `await textLayer.render()` não há check de `cancelled` antes do bloco `prevPageRef`: a execução antiga pode chamar `cleanup()` na página **atualmente exibida** e sobrescrever `prevPageRef` com a página antiga.

Correção sugerida: guardar a instância de `TextLayer` em ref e chamar `.cancel()` no cleanup do effect (o método existe no pdfjs 5.6), e re-checar `cancelled` após o `await textLayer.render()` antes de mexer em `prevPageRef`/container.

### 3. `[nit]` importBook: falha no rollback mascara a mensagem amigável

`src/lib/books.ts:44-52`. Se `booksDeleteFile` lançar dentro do `catch` (ex.: erro de IO), o erro cru do delete substitui a mensagem amigável de PDF inválido/senha. Envolver o rollback em try/catch próprio (logando a falha) e sempre lançar a mensagem amigável.

### 4. `[nit]` Dead code: `sizeBytes`/`size_bytes` nunca é consumido

`src/lib/books.ts:9` e `src-tauri/src/books.rs:20`. O campo é retornado pelo Rust e tipado no front, mas nenhum código o usa (o `Book` não guarda tamanho). O plano o especificou, mas na implementação final ficou morto — remover dos dois lados (o `size` local no Rust continua necessário para o limite de 50 MB). Remoção é do codeAgent do ajuste final.

### 5. `[nit]` books_read_file: checagem de existência antes da validação de path

`src-tauri/src/books.rs:84-86`. O `p.exists()` roda ANTES da validação canonicalize/`starts_with`, então um renderer comprometido pode sondar a existência de qualquer arquivo do disco pela diferença de mensagem ("Book file not found" vs "Access denied"). `read_chat_doc` valida antes de qualquer resposta diferenciada; `delete_chat_doc` tem o mesmo padrão do novo código (retorna `Ok(())` para path inexistente), então é consistência parcial com o existente — vazamento de baixo risco em app desktop, mas fácil de fechar invertendo a ordem (validar o path primeiro, tratar erro de canonicalize de arquivo inexistente como "not found" apenas quando o prefixo já foi validado pelo caminho não-canonicalizado ou movendo o exists() para depois).

### 6. `[nit]` Reader: janela de sobrescrita de `last_opened_at` com `bookRef` defasado

`src/components/Reader/Reader.tsx:55-59` e `167-176`. O mount salva `lastOpenedAt` e só propaga via `onBookChange` quando o `saveBook` resolve; se um flush de `last_page` rodar antes da propagação (só acontece se o save demorar ~500 ms+), ele reconstrói o book a partir do `bookRef` antigo e grava o `last_opened_at` anterior por cima. Janela muito pequena na prática; registrar por completude.

### 7. `[nit]` copyPdfjsAssets não atualiza assets em upgrade do pdfjs-dist

`vite.config.ts` (plugin inline). O copy é pulado se `public/pdfjs/<dir>` já existe, então um upgrade futuro do `pdfjs-dist` fica com wasm/fontes/cmaps velhos até alguém apagar `public/pdfjs` manualmente. Foi o comportamento especificado no plano ("skip se destino já existe"), mas vale um marcador (ex.: arquivo de versão dentro de `public/pdfjs` comparado com a versão do pacote) ou comentário avisando.
