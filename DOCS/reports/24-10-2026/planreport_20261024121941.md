## Fase 1 — Mark e editor

### Etapa 1 — Mark `noteMark` + parse/serialização `==`
- **Arquivos:** `package.json` (adicionar `markdown-it-mark`); criar `src/components/Editor/NoteMark.ts`; `src/components/Editor/extensions.ts`; `src/App.css`.
- **Detalhes:**
  - `NoteMark.ts`: `Mark.create({ name: 'noteMark' })` com `parseHTML: [{ tag: 'mark' }]`, `renderHTML: ['mark', 0]`; `addStorage().markdown`: `serialize: { open: '==', close: '==' }` e `parse: { setup(md) { md.use(markdownItMark) } }` (mesmo padrão do `task-list` do tiptap-markdown).
  - Input rule (Tiptap v3, `markInputRule` ou `addInputRules`): `find: /==([^=\s](?:[^=]*[^=\s])?)==$/`; garantir que não dispara com code mark ativo (verificar `excludes` do code; se necessário, guard explícito `editor.isActive('code')`).
  - Registrar `NoteMark` em `buildBaseExtensions` (ao lado de `HighlightMark`) — obrigatório para não perder a marca no KeepPanel.
  - CSS `.ProseMirror mark`: visual distinto do highlight (que usa `span[data-bg]`/`--hl`): texto e sublinhado em cor de acento quente (âmbar) com fundo sutil, via variável `--nm`, legível nos dois temas; sobrescrever o amarelo default do user agent; `cursor: pointer`.
- **Critérios de aceite:** digitar `==teste==` cria a marca e some os delimitadores; `==` dentro de código inline/bloco não vira marca; trocar de nota e voltar preserva a marca (round-trip `==` → `<mark>` → `==` estável, sem duplicação); markdown persistido contém `==teste==`; nota aberta no KeepPanel não perde a marca; `npm run build` passa.

### Etapa 2 — Botão "Tag" na régua de seleção
- **Arquivos:** `src/components/Editor/formattingActions.ts`, `src/components/Editor/FormattingToolbar.tsx` (só se o render genérico não bastar).
- **Detalhes:** adicionar `'notemark'` ao union `FormatId`; botão `{ id: 'notemark', label: 'Tag', title: 'Notemark — mark this passage (==)' }` no segundo grupo de `FORMATTING_GROUPS` (após `strike`); `isActive`: `editor.isActive('noteMark')`; `runAction`: `chain.toggleMark('noteMark').run()`; incluir `'notemark'` no grupo de marks inline de `insertNewFormattedLine` (mesmo caso de `bold`/`highlight`).
- **Critérios de aceite:** com texto selecionado, clicar "Tag" aplica a marca (visual do §3 do spec); clicar de novo remove preservando o texto; estado ativo quando a seleção está dentro de uma marca.

### Etapa 3 — Menu flutuante ao clicar na marca
- **Arquivos:** criar `src/components/Editor/NoteMarkMenu.tsx`; `src/components/Editor/Editor.tsx` (montar; reusar prop `onAskAi`).
- **Detalhes:** `BubbleMenu` de `@tiptap/react/menus` com pluginKey `monetNoteMarkMenu`; `shouldShow`: seleção vazia E `editor.isActive('noteMark')`. Helper `noteMarkRangeAt(state, pos)`: expande a posição até as bordas do mark contíguo (percorrer o textblock verificando `mark.isInSet`). Ações: **Ask AI** (texto do range → `onAskAi`, mesmo fluxo do botão "Ask AI" da régua); **Copy** (`navigator.clipboard.writeText` do texto do range); **Remove mark** (`setTextSelection(range).unsetMark('noteMark')`). Labels em inglês, no padrão da UI ("Ask AI", "Copy", "Remove mark").
- **Critérios de aceite:** clique na marca abre o menu ancorado nela; as três ações funcionam; "Remove mark" preserva o texto; menu não aparece durante seleção de texto (a régua de formatação é a dona desse caso).

## Fase 2 — Ctrl+P e navegação ao ponto

### Etapa 4 — Extração de marcas + token `has:mark`
- **Arquivos:** criar `src/lib/noteMarks.ts`; `src/lib/noteSearch.ts`.
- **Detalhes:**
  - `extractNoteMarks(content): Array<{ text: string; occurrence: number }>`: remover fenced code blocks e inline code antes; regex `/==([^=\n]+?)==/g`; `occurrence` = índice da marca na nota (ordem do documento).
  - `parseSearchQuery`: novo token `has:mark` (case-insensitive) → campo `marked: boolean` + chip `{ kind: 'marked', label: 'Marcadores' }`.
  - `MD_INLINE_RE` (`noteSearch.ts:45`): incluir `==` para snippets limpos.
  - `searchMarks(notes, text, opts)`: notas com `marked`, match normalizado (`normalizeSearch`) do texto da query contra o texto das marcas; retorna entradas `{ note, markText, occurrence }`, arquivadas por último, limite padrão coerente com o resto da palette.
- **Critérios de aceite:** `has:mark` isolado lista marcas; combinável com `#Caderno`, `type:` e `is:archived`; `==` em código não aparece; snippets de nota não exibem `==`.

### Etapa 5 — Resultados de marca no SearchPalette
- **Arquivos:** `src/components/SearchPalette/SearchPalette.tsx` (+ `.module.css` se preciso).
- **Detalhes:** novo kind `{ kind: 'mark', note, markText, occurrence }`; chip removível "Marcadores" (mesmo estilo dos chips existentes); seção própria ("Marcadores") com header; linha com caderno, título da nota e trecho marcado com o estilo visual da marca (sem `==` literal); nova prop `onSelectMark(note, occurrence)`; placeholder do input passa a citar `has:mark`.
- **Critérios de aceite:** chip aparece/remove com o token; resultados listam uma linha por ocorrência (texto repetido na mesma nota = linhas separadas); Enter/clique dispara `onSelectMark`.

### Etapa 6 — Navegação ao ponto com flash
- **Arquivos:** `src/App.tsx`, `src/components/Editor/Editor.tsx`, `src/App.css`.
- **Detalhes:** estado `pendingNoteReveal: { noteId, occurrence, text, nonce } | null` no App; `onSelectMark` chama `onSelectNote(notebookId, noteId, subjectId)` e seta o reveal. Editor recebe prop `revealRequest` + `onRevealConsumed`; efeito (editor pronto e nota ativa = `noteId`): `doc.descendants` coletando ranges com mark `noteMark` em ordem; escolher por `occurrence` (fallback: primeiro cujo texto casa `text` normalizado); `chain().setTextSelection({from,to}).scrollIntoView().run()`; depois, `view.nodeDOM(from)` → `closest('mark')` → adicionar classe de flash (keyframe de pulso ~1,5 s, remover em `animationend`); consumir o request.
- **Critérios de aceite:** selecionar uma marca no Ctrl+P abre a nota já rolada no trecho, com o range selecionado e o flash visível; ocorrências repetidas navegam para a ocorrência correta; troca normal de nota (sem reveal) não dispara nada.

## Fase 3 — IA

### Etapa 7 — Tool `search_marks` + system prompt
- **Arquivos:** `src/hooks/useChat.ts`.
- **Detalhes:** tool def junto às demais (~3139-3324), gated por `supportsTools && tools.notes` (sem toggle novo). Execução no padrão de `getNoteText`: ler storage na hora (`getNotebooks`, `getNoteSummaries`), respeitar `notesIndexGetDisabledNotebooks()`, carregar conteúdo das notas candidatas, extrair com `extractNoteMarks` (Etapa 4). Parâmetros: `query?` (filtra texto das marcas), `notebook?` (nome parcial do caderno). Retorno limitado por orçamento (padrão `GET_NOTE_*_BUDGET`): trecho, título, caderno, arquivada. Descrição da tool explícita: read-only, não cria/remove marcas, não cria tasks, não inicia pesquisas. System prompt: instruir que `==...==` em notas são NoteMarks do usuário e que referências a trechos marcados devem citar o texto verbatim como `==texto==`.
- **Critérios de aceite:** com "Notes" ligado, "o que eu marquei?" retorna o inventário de marcas com procedência; caderno com IA desligada não aparece; com "Notes" desligado a tool não é oferecida.

### Etapa 8 — `==` clicável no chat + seletor de notas
- **Arquivos:** `src/components/ChatPanel/ChatMessageBubble.tsx`; `src/App.tsx`; criar `src/components/SearchPalette/MarkNotePicker.tsx` (ou pasta própria).
- **Detalhes:**
  - Após `renderMarkdown`, pós-processar o HTML sanitizado com DOMParser: em text nodes fora de `pre`/`code`, envolver `/==([^=\n]+?)==/g` em `<mark data-nm="texto">`. Não mexer no remark nem no whitelist de `src/lib/markdown.ts`.
  - Event delegation no container do balão: clique em `[data-nm]` → prop `onOpenMark(text)` até o `App`.
  - `onOpenMark` no App: buscar nas notas em memória com `extractNoteMarks` (match exato normalizado). 0 → feedback discreto; 1 → `onSelectNote` + `pendingNoteReveal`; >1 → abrir **`MarkNotePicker`**: modal no padrão visual do SearchPalette (overlay+painel), linha por nota com caderno, título, excerpt e data de edição; teclado ↑↓/Enter/Esc; escolha → `onSelectNote` + `pendingNoteReveal`.
- **Critérios de aceite:** resposta da IA com `==texto==` renderiza a marca clicável; `==` dentro de bloco de código da resposta não vira link; clique com múltiplas notas abre o seletor e a escolha navega ao ponto com flash; clique com uma nota navega direto.

## Riscos

| Risco | Mitigação |
|---|---|
| Round-trip instável (`==` duplicando/colapsando entre trocas de nota) | Teste manual explícito na Etapa 1 (padrão dos testes de round-trip do `ParagraphWithBlankLines`); serializer com `open`/`close` simples, sem lógica condicional |
| `markdown-it-mark` casando `==` indesejado em texto legado | Aceito por decisão (Obsidian-like); remoção em 1 clique (R1/Etapa 2-3); documentado no spec (R4) |
| Input rule disparando dentro de código | Guard na Etapa 1; critério de aceite dedicado |
| Mark descartado por editor com schema incompleto (Keep/Reader) | Registro em `buildBaseExtensions` (obrigatório, Etapa 1); teste manual no KeepPanel |
| Custo de `extractNoteMarks` sobre todas as notas a cada tecla no Ctrl+P | Memo por `note.id + updatedAt` (padrão do cache de `noteSearch.ts`); debounce já existente (100 ms) |
| Índice de ocorrência divergente entre markdown (regex) e doc ProseMirror (descendants) | Fallback por texto na Etapa 6; edge case documentado no spec (R8) |
| Falso positivo de `==` em código dentro da resposta do chat | Pós-processamento ignora `pre`/`code` (Etapa 8); critério de aceite dedicado |
