# Plano

## Escopo
Permitir que o modelo, dentro de uma chat-folder, persista fontes web (conteúdo bruto extraído via Tavily `/extract`, sem síntese) como arquivos `.md` numa watched-folder de KB própria daquela pasta — reaproveitando o pipeline de RAG/watched-folders existente (`documents.rs`, chunk+embed, `vec_chunks`). A feature é gated por uma flag por pasta (`webResearchEnabled`, mesmo padrão de `memoryEnabled`). A watched-folder é criada automaticamente (mkdir + insert), marcada visível gravando o próprio ID em `ChatFolder.visibleDocumentIds` (sem campo novo), e resolvida pasta→filhos **dinamicamente** a cada busca RAG no `useChat.ts` — correção que vale para qualquer watched-folder em `visibleDocumentIds`, não só a da IA (corrige também a defasagem hoje existente em `FolderDocumentSelectorModal.tsx`). Uma nova coluna `documents.origin` (`'user' | 'ai'`) diferencia a origem para exibir badge na KB e para apagar fisicamente os `.md` quando a pasta gerada pela IA é removida pela UI (comportamento que não se aplica a watched-folders do usuário).

Decisões de arquitetura já confirmadas (Task Report atualizado + decisão do Orquestrador de 20260723172500) e tratadas aqui como requisitos fechados:
- **Sem campo novo em `ChatFolder`**: o ID da watched-folder entra em `visibleDocumentIds`, mesmo array que `FolderDocumentSelectorModal` já escreve.
- **Resolução dinâmica genérica**: qualquer ID de pasta em `visibleDocumentIds` é expandido para os filhos atuais a cada busca RAG (não só o gerado pela IA).
- **Deleção física apenas para pastas `origin='ai'`**: watched-folders do usuário continuam nunca apagando arquivo físico.

## Observações para o codeAgent

- Endpoint Tavily `/extract` confirmado via documentação oficial (não usado em nenhum outro ponto do código hoje): request `{ urls: string[], format?: 'markdown'|'text', ... }`, response `{ results: [{ url, raw_content, images?, favicon? }], failed_results: [...] }`. Não há campo de título na resposta — por isso a tool `save_web_source` recebe `title` como argumento do próprio modelo (que já viu o título nos resultados de `web_search`/`deep_research` anteriores), não é extraído do `/extract`.
- O comando `documents_scan_watched_folder` (já existente, não precisa ser criado) é suficiente para indexar o `.md` recém-escrito — ele já trata arquivos novos dentro de uma pasta watched de forma genérica (`scan_watched_folder_async`), incluindo chunk+embed via `run_indexing`. Não criar um caminho de indexação paralelo.
- `is_external=1` na pasta criada pela IA (Etapa 3) é intencional e replica exatamente o padrão de `documents_add_watched_folder` — os arquivos filhos entram como `is_external=1` automaticamente pelo `scan_watched_folder_async` de qualquer forma (hardcoded no INSERT de arquivo novo), então não há necessidade de tratamento especial por criança; a única coisa nova que diferencia a pasta da IA é a coluna `origin`.
- Escopo restrito ao pedido: não foi adicionada poda/limite de crescimento da pasta, nem suporte a múltiplas pastas de IA por chat-folder, nem sincronização do nome da pasta de KB quando o usuário renomeia a `ChatFolder` depois de criada — todos esses pontos são explicitamente fora de escopo no Task Report.
