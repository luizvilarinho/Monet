### Etapa 2 — Serializador único em `noteFileText.ts`
- Status: PENDENTE
- Descrição: Reescrever `cleanNoteContentForAi(content, opts)`. Mantém o nome e troca o 2º parâmetro por um objeto de opções:
  ```ts
  export interface NoteAiTextOptions {
    resolveNoteTitle: (noteId: string) => string | undefined
    // commandId → resposta salva; ausente/undefined = bloco ignorado
    resolveEmbed?: (commandId: string) => AiResponse | undefined
    // Presente = expande notas linkadas (1 nível); ausente = só o título (RAG)
    resolveLinkedNoteContent?: (noteId: string) => string | undefined
  }
  ```

  **Formato da resposta embutida (`embedResponseText(id)`)**
  - Busca `resolveEmbed?.(id)` e ignora a resposta quando ela não existe, quando `status === 'error'` ou quando `response.trim()` é vazio.
  - Saída: `${getToggleTitle(r.command)}\n${r.response.trim()}`, ou seja, uma linha de título e o texto como conteúdo normal. `getToggleTitle` vem de `src/components/Editor/commandParser.ts` (puro).

  **Formato da nota linkada (`linkedNoteText(id)`)**
  - Sem `resolveLinkedNoteContent`: mantém o comportamento atual, `[Linked note: <título|untitled>]`.
  - Com o resolver:
    - Se a nota não existe (`content === undefined`), retorna `''`, porque o link está quebrado.
    - Senão, `body = cleanNoteContentForAi(content, { resolveNoteTitle, resolveEmbed })`. A chamada recursiva vai **sem** `resolveLinkedNoteContent`, o que limita a 1 nível e resolve os ciclos.
    - Truncar `body` em `LINKED_NOTE_BUDGET = 2000` chars com o sufixo ` [truncated]`.
    - Saída: `[Linked note: <título>]\n<body>\n[/Linked note]`, ou só `[Linked note: <título>]` quando `body` é vazio.

  **Toggles (trocar `TOGGLE_BLOCK_RE`)**
  - Nova função interna `replaceToggleBlocks(text, renderNode)`:
    - Achar cada `<div data-type="toggle-block"`.
    - Achar o `</div>` correspondente contando a profundidade com `/<div\b|<\/div>/g`. Isso é necessário porque o `taskItem` gera `<div>` interno e a regex lazy quebrava. Sem fechamento, usar até o fim do texto.
    - Parsear o trecho com `document.createElement('template')` + `innerHTML` e substituir pelo texto do walker.
  - Walker DOM → texto (`nodeToAiText`):
    - Texto: `textContent`. As entidades já saem decodificadas.
    - `div[data-type=toggle-block]` e `toggle-block` (aninhado): linha `data-title`, depois os filhos.
    - `p`, `h1`–`h6`, `blockquote`, `pre`: conteúdo + `\n`. `br`: `\n`.
    - `li`: prefixo `- `. Se `data-type="taskItem"`, o prefixo é `- [x] ` ou `- [ ] ` conforme `data-checked`. Conteúdo + `\n`.
    - `label` (checkbox do taskItem): ignorar.
    - `embed-block`: `embedResponseText(data-cmd)`. `linked-note`: `linkedNoteText(data-note-id)`.
    - `task-ref`: `[task]`. `reminder-chip`: `⏰ <data-time>`. `tasks-query`: `[Tasks block: <data-filter>]`. `img`: `[image]`.
    - Demais elementos: recursão nos filhos.
    - O resultado é trimado, e as linhas em branco repetidas são colapsadas no final da cadeia.

  **Ordem da cadeia**
  1. `EMBED_BLOCK_RE` (legado, mantido), `MARKER_RE` e as 3 regex de imagem (como hoje).
  2. Toggles: o walker já trata embed, link, chips e task-ref internos.
  3. `REMINDER_CHIP_RE`, `TASK_REF_RE`, `TASKS_QUERY_RE`.
  4. Por último, os blocos de topo:
     - `EMBED_TAG_RE = /<embed-block\b[^>]*\bdata-cmd="([^"]*)"[^>]*>\s*<\/embed-block>/g` → `embedResponseText`.
     - `LINKED_NOTE_RE` → `linkedNoteText`.
     - Ficam por último para o texto inserido não ser reprocessado.
  5. `BR_RE`, o filtro de `COMMAND_LINE_RE` e o colapso de `\n{3,}` (como hoje).

  **Funções e assinaturas novas**
  - Exportar `collectEmbedIds(content): string[]`: ids de `data-cmd` de `<embed-block`, inclusive dentro de toggles. Uma regex global no texto bruto basta.
  - Exportar `collectLinkedNoteIds(content): string[]`, pelo `data-note-id` de `<linked-note`.
  - Exportar `async loadEmbedResponses(contents: string[], resolveLinkedNoteContent?: (id: string) => string | undefined): Promise<Map<string, AiResponse>>`:
    - Junta os ids de embed de `contents`. Com o resolver, junta também os ids das notas linkadas a cada content (1 nível).
    - Deduplica e chama `storage.getResponsesByIds`.
    - Retorna um `Map` por id.
    - Em erro, `console.warn` e `Map` vazio. A IA segue sem as respostas.
  - `buildNoteFileText(note, resolveNoteTitle, taskContext?, resolveEmbed?)` ganha o 4º parâmetro e chama o serializador sem `resolveLinkedNoteContent`. Assim o RAG fica só com o título da nota linkada.
  - Atualizar o comentário de cabeçalho da função.
  - Não mexer em `EMBED_BLOCK_RE`/`MARKER_RE`/`COMMAND_LINE_RE`: continuam exportados porque `scoreNotes.ts` os usa.
- Arquivos: `src/lib/noteFileText.ts`

## Limitações conhecidas (sem etapa)
- **Resposta em streaming no RAG.** Se o debounce de 10s indexar a nota enquanto a resposta embutida ainda está em streaming, o RAG fica com o texto parcial ou sem ele. A correção acontece na próxima indexação da nota: nova edição ou reconciliação no próximo start do app, conforme o edge case do Task Report.
- **Toggle "Tasks" compartilhado.** O toggle fica no estado `monet:chat-tools`, compartilhado com o chat principal. Ligar no NotesChat liga também lá, que é o comportamento atual de todas as tools compartilhadas.
- **Memória ligada só em pastas novas.** As pastas de caderno que já existem continuam com a memória desligada.
