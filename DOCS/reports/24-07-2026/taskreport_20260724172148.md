# Task: Bibliotecário — sub-pipeline de artigos científicos em acesso aberto (PDF → RAG)

## Objective
Estender o bibliotecário (pipeline em background já implementado para páginas web) com um **segundo sub-pipeline paralelo** que, proativamente a cada turno de pesquisa web (com `webResearchEnabled` ligado), busca **artigos científicos em acesso aberto (OA)** sobre o tópico tratado, baixa o **PDF real** e grava na mesma pasta de KB da IA que já alimenta o RAG. Motivação de produto: `productVision` pede que a IA se ancore no material de estudo do usuário, "não na internet genérica" — papers acadêmicos são material durável/substancial de aprofundamento, encaixe muito melhor que páginas web genéricas. O sub-pipeline **complementa** (não substitui) o de páginas web: ambos ficam ativos e gravam na mesma pasta. A ingestão de PDF já existe (`documents.rs:503` `pdf_extract::extract_text` + scan), então basta colocar o `.pdf` na pasta com nome sensato — sem chunking manual.

## Context
- **Bibliotecário atual (a estender, não reescrever):** `src/lib/librarian.ts` — singleton com `inFlightUrls` Set + `folderChains` Map (serialização por pasta), `enqueueLibrarian` disparado em `onOpenRouterDone` (`useChat.ts`) via `librarianContextRef` (tópico + searchResults + citedUrls), `runPipeline` (dedupe→triagem→extract→julgamento→escrita verbatim→scan→toast). Modelo secundário DeepSeek (`deepseek/deepseek-chat`, `json_object`) via comandos Rust `librarian_triage`/`librarian_judge`.
- **Ingestão de PDF já funciona:** `documents.rs:219` `detect_mime` reconhece `.pdf`; `documents.rs:503-521` extrai texto via `pdf_extract::extract_text` (erro tratado para PDF escaneado/sem texto); `MAX_FILE_BYTES = 50MB` (`documents.rs:49`) — folgado para papers. Crate `pdf_extract` já é dependência.
- **Escrita atual é text-only:** `documents_write_ai_source_file` (`documents.rs:1090`) recebe `String`, valida extensão `.md`, escrita atômica temp→rename já implementada. **Não serve para binário** — precisa de comando irmão para bytes/`.pdf`.
- **Pasta de KB da IA:** `documents_ensure_ai_folder` (idempotente, `origin='ai'`), scan via `documents_scan_watched_folder` (fire-and-forget) — reaproveitados como no pipeline web.
- **HTTP no Rust:** `deep_research_generate_sub_queries`/`web_search_route` (`lib.rs`) mostram o padrão de chamada HTTP a partir do Rust (chave lida via `read_key`, POST a API externa). O cliente HTTP exato para **download de binário** (seguir redirect, timeout, ler bytes) deve ser confirmado no planning (reqwest ou equivalente já presente).
- **E-mail de contato:** o app conhece o e-mail do usuário; Crossref pede User-Agent com e-mail de contato e Unpaywall **exige e-mail real** no parâmetro (recusa `test@example.com`).
- **APIs alvo (todas gratuitas, OA legítimo):** Crossref `api.crossref.org/works` (busca por termos → title/DOI/year/type), Unpaywall `api.unpaywall.org/v2/{doi}?email=...` (`is_oa` + `best_oa_location` PDF URL), DOAJ `doaj.org/api/search/articles/{query}` (fallback; periódicos 100% OA, já vêm com link de texto completo).

## Requirements
- **Extração de termos acadêmicos:** o tópico do chat não é query acadêmica boa. Uma chamada ao modelo secundário (DeepSeek, mesmo padrão dos comandos existentes) transforma a pergunta/tópico do turno em termos de busca para o Crossref. Pode ser combinada com a triagem existente ou ser um comando novo — decisão do plano.
- **Busca Crossref:** consultar `api.crossref.org/works` com os termos, header `User-Agent` incluindo e-mail de contato. Coletar candidatos (title, DOI, year, type, abstract quando disponível). Limitar a um número pequeno de candidatos.
- **Filtro de relevância (barra conservadora):** Crossref é ruidoso — antes de baixar, julgar os candidatos (título + abstract quando houver) contra o tópico do usuário via modelo secundário, mantendo só os genuinamente on-topic e substanciais. **Cap por turno** (ex.: no máximo N papers) para não inundar a KB.
- **Resolução de OA:** para cada DOI aprovado, consultar Unpaywall (`?email=<e-mail real>`); se `is_oa`, pegar o PDF de `best_oa_location`. Fallback DOAJ quando Unpaywall não retornar OA. DOIs sem OA são descartados silenciosamente.
- **Download + validação no Rust (não no frontend):** comando Rust novo que baixa o binário da URL do PDF (seguir redirects, timeout, User-Agent), e **valida que o conteúdo começa com a assinatura `%PDF`** antes de aceitar — rejeita HTML de landing/erro/login. CORS e binário exigem que isso viva no Rust, não no webview.
- **Escrita binária atômica:** comando Rust novo (ou generalização) que grava os bytes do PDF na pasta de KB da IA, aceitando extensão `.pdf`, com o mesmo temp→rename, sob `MAX_FILE_BYTES`, exigindo `origin='ai'` na pasta (como o comando de `.md`).
- **Nome de arquivo:** `{ano}_{titulo-em-slug}.pdf` (sensato e legível na KB). Dedupe por nome/DOI antes de baixar (evita refetch).
- **Persistência na mesma pasta:** usar `documentsEnsureAiFolder` (mesma pasta do pipeline web), registrar na `visibleDocumentIds` (mesmo callback já existente), disparar o scan existente.
- **Feedback:** reaproveitar o toast "N sources saved" — papers e páginas web contam juntos como fontes salvas. Operação **silenciosa** (modo oportunista), como o pipeline web.
- **Complementaridade:** o pipeline de páginas web permanece ativo e inalterado no comportamento. Os dois rodam no mesmo turno, serializados pela mesma cadeia por pasta.

## Constraints
- Só fontes **em acesso aberto** (Unpaywall/DOAJ). Nunca baixar conteúdo pago/pirata (nada de Sci-Hub). Rota legalmente limpa é requisito, não preferência.
- Download de binário e escrita de bytes **no Rust** (CORS + binário inviáveis no webview). Validar `%PDF` antes de salvar — nunca gravar HTML como se fosse PDF.
- Conteúdo salvo é o **PDF real verbatim** — o modelo secundário só decide (query/relevância), nunca reescreve/resume.
- Reaproveitar a infra do bibliotecário: mesma pasta de KB da IA, mesmo `enqueueLibrarian`/serialização/in-flight, mesmo scan, mesmo toast. Não criar storage/pasta paralelos.
- E-mail de contato para Crossref/Unpaywall deve ser **real** (do usuário/config), nunca placeholder — Unpaywall recusa e-mails de teste.
- Respeitar uso polido das APIs: throttle no loop por-DOI, User-Agent identificável, cap de candidatos.
- **Cap conservador de papers por turno** — despejar muitos PDFs não pedidos contraria `productVision` ponto 4 (a IA não se impõe). Barra de relevância conservadora + cap são o freio.

## Edge Cases
- **Taxa de OA ~50%:** muitos DOIs on-topic não terão PDF baixável — descartar em silêncio; a feature salva "alguns papers abertos", não "os papers-chave". Comportamento esperado, não bug.
- **Link OA quebrado devolve HTML** (landing/login/erro) em vez do arquivo — o check `%PDF` rejeita; não gravar.
- **Ruído do Crossref:** resultados tangenciais/de outro campo — o filtro de relevância + cap contêm; na dúvida, não salvar.
- **Abstract ausente no Crossref:** julgar só pelo título é fraco — decidir no plano se aceita, busca abstract em outra fonte, ou é mais conservador nesse caso.
- **PDF escaneado sem texto:** `pdf_extract` já erra nesse caso no scan — um PDF só-imagem viraria arquivo morto no RAG. Decidir no plano se detecta/pula antes de salvar ou aceita.
- **Rate limits:** loop por-DOI no Unpaywall + Crossref — throttle e User-Agent com e-mail; usar o "polite pool".
- **Dedupe:** mesmo paper em turnos diferentes — dedupe por nome de arquivo/DOI + o `inFlightUrls`/serialização por pasta já existentes.
- **PDF grande (perto de 50MB):** aceito pelo limite atual; download pode ser pesado — background absorve.
- **Concorrência com o pipeline web na mesma pasta:** ambos passam pela mesma cadeia `folderChains` por pasta — sem escrita concorrente.
- **Flag desligada / chat fora de pasta:** sub-pipeline acadêmico é no-op, igual ao web.
