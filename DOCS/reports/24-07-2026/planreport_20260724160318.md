## Escopo

dentro de `src/hooks/useChat.ts` por um pipeline em background orquestrado por código
(o "bibliotecário"), disparado no fim do turno (`onOpenRouterDone`). O modelo principal
volta ao comportamento pré-feature (rodada 1 com tools → rodada 2 texto). Um modelo
secundário barato (DeepSeek via OpenRouter) faz duas decisões discretas com saída JSON:
**triagem** (quais URLs valem extract) e **julgamento** (qual conteúdo real presta). O
conteúdo salvo é o markdown do `tavilyExtract` **verbatim** com cabeçalho de proveniência.
Feedback ao usuário = toast "N fontes salvas na base de conhecimento".

## Decisão técnica confirmada — DeepSeek + JSON

**Usar `response_format: { type: "json_object" }` (JSON mode), NÃO `json_schema` strict.**
DeepSeek (`deepseek/deepseek-chat`) via OpenRouter suporta JSON mode de forma confiável;
o suporte a `json_schema` strict varia por rota/provider e pode ser rejeitado. O prompt
deve descrever explicitamente o shape JSON esperado, e o parsing tolerante (parse direto →
fallback extraindo o primeiro `{...}`/`[...]`) — idêntico ao de
`deep_research_generate_sub_queries` — cobre o edge case "JSON malformado". **Nunca gravar
sem uma decisão JSON parseada com sucesso**; em qualquer falha a função Rust retorna
`Ok(vec![])` (nada a salvar). Constante interna `LIBRARIAN_MODEL = "deepseek/deepseek-chat"`
em `lib.rs` (não exposta ao usuário; Coordenador pode trocar o id depois).

## Riscos / pontos que ainda podem precisar do Coordenador

1. **Id do modelo DeepSeek** (`deepseek/deepseek-chat`): escolhido como padrão OpenRouter.
   Se o Coordenador preferir outra rota/variante DeepSeek (ex.: reasoner), é troca de 1
   constante em `lib.rs`. Confirmado no plano: usar **`json_object`** (não `json_schema`
   strict) + parsing tolerante.
2. **Prioridade-por-citação é best-effort** (Etapa 9.3): o texto final lido de
   `conversationsRef` pode, em raras corridas last-chunk↔done, estar 1 render atrás. Como a
   citação só reordena a barra conservadora (não altera correção), foi aceito como
   trade-off. Sinalizo caso o Coordenador queira captura determinística (custaria capturar
   o texto dentro do updater de `updateMessages`, padrão mais frágil).
3. **Criação preguiçosa da AI folder:** o pipeline só cria a pasta "Web research — X" e a
   adiciona à seleção quando ≥1 fonte é aprovada (evita pastas vazias no modo oportunista).
   A localização da pasta existente para dedupe usa `visibleDocumentIds`; se o usuário
   remover a pasta da seleção, um extract pode se repetir (custo), mas o dedupe de escrita
   (parentFolderId+filename) + `documentsEnsureAiFolder` idempotente impedem duplicata em
   disco. Comportamento aceitável (belt-and-suspenders do Task Report).
4. **Crescimento monotônico da KB** (sem poda/eviction): fora de escopo por decisão do Task
   Report; a barra conservadora da triagem é o único freio. Registrado como esperado.
5. **Deep research não alimenta o bibliotecário** no v1: só `web_search`/`webSearch`. Se o
   Coordenador quiser persistir fontes de deep research também, é escopo adicional — não
   incluído.
