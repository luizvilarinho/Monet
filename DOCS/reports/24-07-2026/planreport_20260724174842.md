# Plano — Sub-pipeline acadêmico do bibliotecário (Crossref → Unpaywall → PDF → RAG)

**Timestamp:** 20260724174842
**Base:** taskreport_20260724172148.md + explorerreport_20260724172653.md + decisões travadas do Coordenador/Orquestrador.

## Escopo

Estender o bibliotecário com um **segundo sub-pipeline acadêmico** que, proativamente em todo turno de pesquisa web (com `webResearchEnabled` ligado), transforma a pergunta do turno em query bibliográfica, busca artigos em acesso aberto no **Crossref**, filtra por relevância (barra conservadora, cap 3/turno), resolve o PDF OA via **Unpaywall**, baixa+valida `%PDF` no Rust e grava o PDF real verbatim na **mesma pasta de KB da IA** que já alimenta o RAG. Roda **sequencial após** o bloco web, dentro do mesmo `runPipeline`, compartilhando AI folder, `inFlightUrls`, dedupe em disco, um único scan e um único toast somado (web + papers).

**Fora do v1 (travado):** DOAJ; detecção de PDF escaneado antes de salvar (aceitar como está); busca de abstract externo; qualquer mudança no Cargo.toml; qualquer mudança em `useChat.ts`/`enqueueLibrarian`; qualquer mudança no comando/pipeline web `.md` existente.

## Notas anti-overengineering / riscos para o Coordenador

1. **Fork de CORS (Etapa 6):** o Caminho B (comandos Rust) só deve ser codado se o teste 6.0 falhar. O default (frontend fetch) é o esperado — Crossref/Unpaywall enviam `Access-Control-Allow-Origin: *`. Não implementar os dois caminhos "por precaução".
2. **User-Agent no fetch:** no Caminho A, o polite pool do Crossref é alcançado **só** pelo `mailto=` query param — o header `User-Agent` é forbidden no webview e descartado. Isso é suficiente para o pool polite; não há workaround necessário no v1. (No download do PDF, que é sempre Rust, o User-Agent real vai no client builder.)
3. **PDF escaneado (travado):** aceito como está — sem detecção antes de salvar. Vira "arquivo morto" cosmético (o guard `documents.rs:520` impede poluição do RAG). Nenhum código para isso no v1.
4. **Latência silenciosa:** a fase acadêmica é serial (query→Crossref→relevância→loop Unpaywall→downloads de MBs) e roda em background fire-and-forget; o toast somado pode aparecer bem depois do fim do turno. Comportamento esperado do "modo oportunista", não bug.
5. **`max_tokens: 300` em `librarian_decide`:** suficiente para 1-2 queries e até ~8 DOIs. Manter `rows=8` no Crossref; não aumentar sem revisitar o teto.
6. **Crescimento monotônico da KB:** sem poda entre turnos (mesmo risco já registrado do pipeline web); PDFs crescem mais rápido que `.md`. Fora do escopo v1 — só registrado. A barra de relevância + cap 3/turno são o único freio.

**Pronto para execução:** nenhum ponto exige decisão adicional do Coordenador antes de codar. As duas escolhas de produto abertas pelo explorer já estão travadas (PDF escaneado = aceitar; abstract ausente = julgar por título com barra extra-conservadora). O único "fork" é técnico e auto-decidido pelo teste de CORS na Etapa 6.0.
