# Task: Web research persistida via "bibliotecário" (pipeline em background orquestrado por código)

## Objective
A feature de gravação de fontes web na KB por chat-folder já existe, mas foi implementada como uma coreografia de tool-calling multi-rodada (`web_search` → `read_web_source` → `save_web_source` → texto) executada pelo modelo principal no turno vivo. Esse mecanismo gerou 5 sessões de bug (loop de rodadas com refs compartilhados, janela de `isStreaming` destravando o input, rodada final vazia travando a bolha, teto `MAX_TOOL_ROUNDS` insuficiente, modelo negando a própria tool) — todas sobre o *mecanismo de orquestração*, não sobre a feature. O objetivo é **substituir essa coreografia por um pipeline em background orquestrado por código** (um "bibliotecário"), disparado automaticamente após cada busca web, usando um modelo secundário barato (DeepSeek via OpenRouter) apenas para decisões discretas de julgamento com saída JSON. O modelo principal volta ao comportamento pré-feature (buscar e responder em 1–2 rodadas). Toda a infraestrutura de persistência (comandos Tauri, extract Tavily, dedupe por hash, RAG dinâmico pasta→filhos, badge "AI-generated", deleção física condicional) já existe e é reaproveitada — não se reconstrói nada disso.

## Requirements
### Limpeza da coreografia

### Pipeline do bibliotecário (novo, orquestrado por código)
- Nova função de pipeline no frontend, **disparada por código** logo após o resultado de `web_search` retornar — nunca pelo modelo principal. O turno do usuário termina normalmente; o pipeline roda depois, sem adicionar latência percebida.
- Etapas do pipeline, nesta ordem:
  1. **Dedupe:** descartar URLs cujo `.md` (nome = `hashUrlToFilename(url)`) já exista na pasta de KB da IA daquela chat-folder.
  2. **Triagem:** uma chamada ao modelo secundário (DeepSeek) recebendo a pergunta do usuário + snippets da busca, retornando **JSON estruturado** com as URLs que valem o extract (0 a N). No modo oportunista, URLs que o modelo principal citou na resposta ganham prioridade.
  3. **Extract:** `tavilyExtract` em lote apenas nas URLs candidatas.
  4. **Julgamento:** uma chamada ao modelo secundário (DeepSeek) lendo o conteúdo real extraído e decidindo, por URL, se presta — descartando paywall/teaser/boilerplate (caso real observado: preview público do Medium). Saída **JSON estruturada** (aprovado/rejeitado por URL).
  5. **Persistência:** para as aprovadas, gravar o **markdown do `tavilyExtract` como está** (com o cabeçalho de proveniência já existente: título, URL, data) via `documentsEnsureAiFolder` + `documentsWriteAiSourceFile`. **Sem passo de reescrita/limpeza por modelo** — o modelo só julga, nunca reescreve.
  6. **Indexação:** disparar `documentsScanWatchedFolder` na pasta (fire-and-forget, como já é hoje).
  7. **Feedback:** evento de UI "N fontes salvas na base de conhecimento" — **não** texto do modelo principal.
- **Dois modos de gatilho:**
  - **Explícito:** o usuário/modelo pediu claramente para salvar ("salva isso"). O pipeline roda com barra de aprovação baixa (só o julgamento de qualidade filtra: paywall/lixo). Falhas devem ser **visíveis na UI** (o usuário pediu).
  - **Oportunista:** roda após buscas comuns, com barra de relevância alta na triagem — só salva o que for genuinamente durável. Falhas são **silenciosas**.
- **Modelo secundário:** DeepSeek via OpenRouter, fixo/config interna (decisão do sistema, não exposta ao usuário). As duas chamadas (triagem, julgamento) usam saída JSON estruturada.
- **Gate por flag:** todo o pipeline (inclusive a chamada de triagem) só roda quando `webResearchEnabled` da chat-folder estiver ligado. Desligado, nenhuma chamada ao modelo secundário acontece.

## Constraints
- Reaproveitar 100% a infra existente listada em Context — não inventar storage/paralelo, não recriar comandos Tauri, não reintroduzir tools de save no modelo principal.
- Conteúdo salvo é a fonte extraída pelo Tavily, **verbatim** — nunca uma reescrita/síntese/resumo do modelo (productVision ponto 3). O modelo secundário só decide (JSON), nunca edita o texto.
- Não usar/alterar o campo `memory` da pasta.
- O pipeline roda **após** o fim do turno conversacional — não pode bloquear nem atrasar a resposta ao usuário.
- Custo do caso comum (nada durável): 1 chamada barata de triagem + 0 extracts. O extract (caro) só ocorre em URLs que passaram na triagem.
- Escrita de arquivo deve ser atômica (nome temporário → rename no fim) para não deixar `.md` parcial indexável se o app fechar no meio.
- Feedback ao usuário é evento de UI, não texto injetado no modelo principal.

## Edge Cases
- **Poluição da KB (modo oportunista):** a barra de relevância da triagem é o único freio contra degradação do RAG ao longo do tempo. Deve ser deliberadamente conservadora (na dúvida, não salvar), coerente com productVision ponto 4 (a IA não se impõe). **Poda/eviction está fora de escopo** — a pasta cresce monotonicamente; registrar isso como comportamento esperado, não bug.
- **Concorrência de pipelines:** buscas rápidas em sequência disparam múltiplos pipelines. Precisa de um `Set` in-flight (chaveado por hash de URL) + serialização/idempotência por pasta para evitar extract duplicado, escrita concorrente e "scan storm".
- **Dedupe TOCTOU:** dois pipelines checando "arquivo existe?" antes de qualquer um gravar podem ambos extrair/gravar a mesma URL. O `Set` in-flight em memória cobre isso além da checagem em disco.
- **Corrida save↔RAG:** fonte salva em background pode não estar indexada quando o usuário pergunta algo relacionado no turno imediatamente seguinte. **Aceitável** — "recuperável na mesma sessão" é satisfeito, só não é instantâneo. Registrar como esperado.
- **App fecha no meio do pipeline:** o job in-flight morre (aceitável pré-launch); a escrita atômica garante que não sobra `.md` parcial/corrompido para o scan indexar.
- **Falha no modo explícito:** Tavily fora do ar / chave inválida / DeepSeek falhando quando o usuário pediu explicitamente → erro visível na UI, nunca silêncio.
- **JSON malformado do DeepSeek:** tratar como "nada a salvar" (fallback silencioso no oportunista; erro visível no explícito). Nunca gravar sem uma decisão de aprovação válida parseada.
- **Flag desligada:** nenhuma chamada de triagem/julgamento nem extract acontece; pipeline inteiro é no-op.
- **Chats fora de uma pasta:** sem chat-folder não há `webResearchEnabled` nem RAG — feature inteira é no-op, já garantido por viver em campos de `ChatFolder`.
