# Task: Pasta de documentação .md no Library (leitura em modo árvore)

## Objective

Permitir que o usuário selecione uma pasta do computador no Library e navegue pelos arquivos `.md` dela (incluindo subpastas) em uma visão de árvore, abrindo os documentos para leitura de forma confortável — experiência análoga à leitura de livros (EpubReader), mas em vez do sumário do livro, o menu lateral lista os documentos `.md` da pasta selecionada. O caso de uso é ler documentação de softwares guardada em arquivos Markdown locais.

## Context

- Módulo Library (`src/components/Library/`) e Reader (`src/components/Reader/`), especialmente o `EpubReader` (navegação por sumário + leitura), que é a referência de UX a imitar.
- Integração com o filesystem via Tauri (permissões/capabilities em `src-tauri/capabilities/`, comandos em `src-tauri/src/`).
- Documentação de entrada: `DOCS/docs.menu.md`.

## Requirements

- Usuário consegue escolher uma pasta do computador a partir do Library (seletor de pasta).
- O Library passa a listar os arquivos `.md` da pasta em modo árvore, refletindo a estrutura de pastas e subpastas (subpastas ajudam a organizar a documentação).
- Ao abrir um documento `.md`, a leitura acontece em uma experiência parecida com a de livros: área de leitura confortável + menu lateral com a árvore de documentos da pasta (no lugar do sumário do livro).
- Navegação entre documentos da pasta sem sair do modo de leitura.

## Constraints

- Seguir os padrões de arquitetura e stack descritos em `DOCS/specs/systemSpecification.md` (Tauri + React + TS, CSS modules, variáveis de `src/App.css`).
- Não importar o conteúdo dos `.md` para dentro das notas do Monet: são arquivos externos lidos da pasta (a menos que o explorer recomende o contrário).
- Acesso ao disco deve respeitar o modelo de permissões do Tauri (fs scope / capabilities), sem gambiarras de segurança.
- Reaproveitar o máximo possível do Reader/EpubReader e dos componentes de lista existentes antes de criar componentes novos.

## Edge Cases

- Pasta com muitos arquivos/subpastas (desempenho da árvore).
- Arquivos `.md` com encoding variado (UTF-8 com/sem BOM, possivelmente outros).
- Pasta removida/renomeada ou sem permissão de leitura depois de selecionada.
- Arquivos que mudam no disco enquanto a pasta está aberta (criar/editar/excluir `.md`).
- Links relativos entre os `.md` da pasta (clicar num link abre outro documento da árvore?) e imagens relativas referenciadas pelos `.md`.
- Markdown variants: frontmatter YAML no topo, tabelas, blocos de código.
- Colisão com funcionalidades atuais do Library (livros/documentos já existentes) — a pasta selecionada não pode quebrar o que já funciona.
