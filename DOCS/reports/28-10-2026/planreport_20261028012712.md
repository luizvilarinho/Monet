# Plano — Pasta de documentação .md no Library (leitura em modo árvore)

**Task report:** `DOCS/reports/28-10-2026/taskreport_20261028011506.md`
**Explorer report:** `DOCS/reports/28-10-2026/explorerreport_20261028011732.md`

## Escopo

Permitir selecionar uma pasta do computador no Library, dar um **nome/alias** a ela (persistido junto com o path), listar os `.md` (com subpastas) em árvore e ler os documentos num componente novo (`DocsReader`) com UX análoga ao `EpubReader`: painel lateral com a árvore no lugar do sumário, área de leitura confortável e navegação entre documentos sem sair do leitor. **Watcher de filesystem em tempo real (v1)**: mudanças externas (criar/editar/excluir/renomear `.md`, inclusive em subpastas) refletem automaticamente na árvore e no documento aberto. Links relativos entre `.md` abrem o documento correspondente da árvore. Nada é importado para as notas/banco do Monet.

### Decisão: watcher com crate `notify` (não polling)

- **Escolha:** crate `notify` no Rust + eventos Tauri (`app.emit`) para o frontend, com comandos próprios `docs_watch_start`/`docs_watch_stop`.
- **Justificativa:** (1) o padrão do projeto já é backend Rust emitindo eventos consumidos pelo frontend via `listen` (`documents://status`, `openrouter://...`, `open-note`) — o watcher segue exatamente esse molde; (2) polling (re-invocar `docs_tree` em intervalo) não é "tempo real" como o Coordenador pediu, re-varre a árvore inteira a cada tick (custo em pastas grandes, um dos edge cases) e não detecta renomeação de forma confiável; (3) `notify` no Windows usa `ReadDirectoryChangesW`, é recursivo nativamente e barato. O debounce de eventos fica no frontend (300 ms), mantendo o Rust simples (emite um evento por batch do notify).
- **Fora da v1 (confirmado):** imagens relativas nos `.md`, painéis Chat/Notes/grifos no leitor de docs.

### Etapa 1 — Comandos Rust de árvore e leitura (`docs_tree`, `docs_read_file`)

- Descrição: Criar o módulo `src-tauri/src/docs_folder.rs` com dois comandos, seguindo o padrão de sandbox de `books.rs` (`canonicalize` + `starts_with` na raiz + rejeição de `..`, nunca confiar em path do frontend):
  - `docs_tree(root: String) -> DocsTreeNode`: varredura recursiva (modelo: `collect_files_recursive` em `src-tauri/src/documents.rs:2104`) retornando a árvore de diretórios contendo apenas arquivos com extensão `.md` (case-insensitive). Regras: ignorar symlinks, pastas ocultas (nome começando com `.`) e entradas com erro de leitura (logar com `eprintln!` e seguir); limites de segurança para pastas gigantes — profundidade máx. 10 e total máx. 5000 arquivos `.md` (ao atingir o teto, parar a varredura silenciosamente; o frontend não precisa saber). Struct serializada com `#[serde(rename_all = "camelCase")]`:
    ```rust
    pub struct DocsTreeNode {
        name: String,              // nome do arquivo/pasta
        rel_path: String,          // path relativo à raiz, separador "/"
        is_dir: bool,
        children: Vec<DocsTreeNode>, // vazio em arquivos
    }
    ```
    Ordenação: pastas antes de arquivos, ambos em ordem alfabética case-insensitive. Diretórios que não contêm nenhum `.md` (nem em subpastas) são omitidos. Validar a raiz no início (`canonicalize`, erro amigável "folder not found or not readable" se falhar).
  - `docs_read_file(root: String, rel_path: String) -> String`: resolve `root/rel_path`, valida com `canonicalize` + `starts_with` na raiz canonicalizada + rejeição de `..`, exige extensão `.md`, lê bytes e decodifica com `String::from_utf8_lossy`, removendo BOM UTF-8 (`\u{FEFF}`) se presente. Retorna o texto (não bytes) — difere de `books_read_file` porque o consumo é direto pelo renderer de Markdown.
  - Registrar o módulo (`mod docs_folder;`) e os dois comandos no `invoke_handler` de `src-tauri/src/lib.rs` (bloco `tauri::generate_handler!`, ~linha 1746). Nenhuma permissão nova em `src-tauri/capabilities/default.json` (comandos próprios não dependem de plugins).
