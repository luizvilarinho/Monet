### Decisões fixadas neste plano (o codeAgent não deve reabrir)

1. **Cores/tokens** (em `src/App.css :root`):
   - `--accent-task: #ef9f27` (laranja = task)
   - `--accent-danger: #e05555` (vermelho = Overdue)
   - `--dot-content: var(--accent)` (roxo = nota com conteúdo)
   - `--dot-activity: var(--accent-ai)` (verde = atividade hoje)
   - O dot atual "nota com checklist pendente" (`.dotPurple`, `#9370db`) ficaria indistinguível do novo roxo de conteúdo. Por isso ele vira **anel roxo vazado** (`background: transparent; box-shadow: inset 0 0 0 1px var(--dot-content)`), com o mesmo tamanho. Nenhuma cor nova é introduzida para ele.
   - `--accent-warn` continua existindo para o banner de erro. Não reutilizar `--accent-warn` para tasks.
2. **Datas:** todas as chaves de dia são `YYYY-MM-DD` em horário **local**. `created_at`, `updated_at` e `completed_at` são epoch ms (INTEGER), como as demais tabelas.
3. **Agrupamento na TasksView** (tasks abertas = `todo` | `doing`):
   - `Overdue`: `due_date < today`
   - `Today`: `due_date === today`
   - `This week`: `today < due_date <= sábado da semana corrente` (semana começa no domingo, igual a `DAY_LABELS` do Calendar)
   - `Later`: `due_date` depois disso
   - `No date`: sem `due_date`
   - `Done`: status `done` ou `dropped`, ordenadas por `completed_at ?? updated_at` desc, limitadas às 50 mais recentes, grupo colapsado por padrão.
   - Ordenação dentro dos grupos abertos: `due_date` asc e depois `sort_order` asc.
4. **Período no Calendar** (função pura `taskSpan`): task aberta com `due_date >= today` cobre `[dayKey(created_at), due_date]`. Se `due_date < dayKey(created_at)` (prazo anterior à criação), cobre só `due_date`. Task aberta sem prazo cobre só `today`. Task aberta com `due_date < today` não tem período: é overdue. `done`/`dropped` nunca têm período. `dropped` nunca aparece no Calendar.
5. **`reschedule_count`** incrementa só quando `prev.dueDate !== null` e o novo `dueDate` é não-nulo e diferente. Limpar o prazo não incrementa.
6. **`completed_at`**: ao passar para `done` (vindo de outro status) recebe `now`; ao sair de `done` vira `null`. `dropped` não grava `completed_at`.
7. **Clique no checkbox de item vinculado na nota**: grava na nota (`setNodeMarkup checked`) **e** na tabela (`done` se marcou, `todo` se desmarcou, inclusive vindo de `doing`). A tabela nunca escreve em `note.content`.
8. **Exclusão de task**: botão "Delete task" no painel de detalhe (com `useConfirm`). É o que torna possível o edge case "task-ref para task inexistente". Nenhuma outra exclusão.
9. **Criação de projeto**: só no seletor de projeto do painel de detalhe da TasksView (nome + caderno vinculado opcional). O popover "Add to Tasks" só **seleciona** projeto, não cria.
