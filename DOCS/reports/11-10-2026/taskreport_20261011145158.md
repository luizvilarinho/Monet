# Task: Tasks — gerenciamento de tarefas integrado ao Calendar (MVP)

## Objective
Criar uma pasta especial **Tasks** (análoga ao Calendar) com gerenciamento de tarefas estruturadas, permitindo promover um item de checklist (`- [ ]`) de qualquer nota a task via a opção **"Add to Tasks"** do BubbleMenu, e exibir as tasks ativas no Calendar em laranja, diferenciadas das notas editadas. O objetivo é que o usuário consiga rastrear o que ficou pendente, algo que hoje as checkboxes soltas nas notas (e o RAG) não resolvem.

## Context
- Calendar: `src/components/CalendarView/`, `src/lib/calendar.ts` (`CALENDAR_NOTEBOOK_ID = 'calendar'`), bootstrap e roteamento em `src/App.tsx`, `NotebookList` trata o caderno especial.
- Editor/Tiptap: `src/components/Editor/` — `extensions.ts` (TaskList/TaskItem), `FormattingToolbar.tsx` (BubbleMenu), `ReminderChip.ts`/`ReminderChipView.tsx`/`RemindersContext.tsx` como **padrão de referência** para um chip inline serializado em markdown cujo estado vive fora do conteúdo da nota.
- Persistência: tabelas do frontend via tauri-plugin-sql (`src/storage/tauri.ts`), migrations em `src-tauri/src/lib.rs`, tipos em `src/types/index.ts`.
- Escopo = Fase 1 (MVP) do estudo aprovado. Kanban, cores por projeto, drag para reagendar, notificações de vencimento, `/task`, varredura de checkboxes e tool de tasks no chat ficam **fora**.

## Requirements
- **Banco (nova migration):**
  - `tasks`: `id`, `title`, `status` (`todo` | `doing` | `done` | `dropped`), `project_id` (nullable), `due_date` (`YYYY-MM-DD`, nullable), `description` (nullable), `created_at`, `updated_at`, `completed_at` (nullable), `source_note_id` (nullable), `reschedule_count` (default 0), `sort_order`.
  - `task_projects`: `id`, `name`, `color` (nullable), `notebook_id` (nullable — vínculo opcional com caderno), `created_at`, `updated_at`.
- **Pasta especial Tasks:** caderno especial fixo (como o Calendar: sem rename/delete/drag, ícone próprio na lista). Ao abrir, mostra a view de Tasks no lugar da lista de notas.
- **View de Tasks:** lista agrupada em `Overdue` (vermelho), `Today`, `This week`, `Later`, `No date`, `Done` (recentes, colapsado). Filtro por projeto. Criar task manualmente. Clicar numa task abre painel de detalhe para editar título, status, projeto, prazo, descrição, com link **"Open source note"** quando houver `source_note_id`. Permitir criar projeto a partir do seletor.
- **"Add to Tasks" (BubbleMenu):** aparece quando a seleção está dentro de um ou mais `taskItem` que ainda não são task. Abre popover com prazo (vazio por padrão) e projeto (sugere o projeto vinculado ao caderno da nota de origem, se existir); Enter confirma. Seleção com vários itens cria várias tasks.
- **Vínculo sincronizado nota ↔ task:**
  - O `taskItem` promovido recebe uma referência inline serializada no markdown (ex.: `<task-ref data-id="...">`), renderizada como pill laranja com o prazo.
  - O estado do checkbox de um item vinculado reflete o status da tabela; marcar/desmarcar na nota atualiza a task (`done`/`todo`), e mudar o status em Tasks reflete na nota — **sem reescrever `note.content`** (mesmo princípio do `reminder_state`).
  - Ao salvar a nota, o texto do item vinculado atualiza o `title` da task.
  - Apagar o item da nota não apaga a task.
- **Regras de datas:**
  - Mudar o `due_date` de uma task que já tinha prazo incrementa `reschedule_count`; exibir "rescheduled N×" quando > 0.
  - `completed_at` é gravado ao marcar `done` e limpo ao reabrir.
- **Integração com Calendar:**
  - Período de exibição de uma task aberta (`todo`/`doing`): de `created_at` até o `due_date` atual (estende ou encolhe se o prazo mudar).
  - Task aberta **sem prazo** aparece apenas em **hoje** enquanto estiver aberta.
  - Grade: marcador laranja nos dias em que há task ativa; marcador laranja destacado no dia do prazo.
  - Abaixo do calendário, seção **Tasks** (cards laranja com checkbox para concluir) acima da seção de notas editadas existente (que mantém a cor atual).
  - Dia passado selecionado: mostra também as tasks concluídas naquele dia (por `completed_at`), riscadas.
  - Task vencida e não concluída deixa de ser pintada no período e aparece num bloco **Overdue** vermelho no topo do dia de hoje até ser concluída, adiada ou dropada.
  - Botão "+ task" no dia selecionado cria task com prazo = aquele dia.
- Clicar num card de task no Calendar abre a task na view de Tasks.
- Toda a UI em inglês.

## Constraints
- Seguir o padrão do Calendar para o caderno especial e o padrão do ReminderChip para o nó inline; não reescrever `note.content` a partir da tabela.
- Tabelas são de propriedade do frontend (tauri-plugin-sql), como `notebooks`/`notes`/`books`.
- Drag-and-drop dentro do Tiptap: não usar HTML5 nativo (não necessário no MVP).
- Projeto em pré-lançamento: migrations podem ser aditivas sem migração de dados legados.
- Remover código morto; seguir estilo do código vizinho; UI consistente com o tema atual (light/dark), laranja como cor de task via token.
- Fora de escopo: Kanban, cores por projeto na UI, drag para reagendar, notificações, slash command `/task`, varredura de checkboxes, tool de tasks no chat, recorrência, prioridade, tags, subtasks.

## Edge Cases
- `task-ref` apontando para task inexistente (apagada): o item vira checkbox comum, sem quebrar o editor.
- Mesmo `task-ref` copiado/colado em outra nota ou duplicado: não criar task nova; definir comportamento consistente (ambos referenciam a mesma task).
- Nota de origem apagada: task permanece; "Open source note" some ou fica desabilitado.
- Seleção mista (itens de checklist + texto comum, ou itens já promovidos): só promove os elegíveis.
- Task criada com prazo anterior à data de criação: tratar como vencida (Overdue), sem período invertido.
- Status `dropped`: não aparece no Calendar nem em Overdue; aparece só no grupo Done/arquivo da view de Tasks.
- Item vinculado marcado na nota enquanto a task está `doing`: vira `done`; desmarcado volta para `todo`.
- Virada de dia com o app aberto: agrupamentos (Today/Overdue) e o Calendar recalculam.
- Janelas secundárias (assistant/keep) não devem divergir do estado das tasks exibido na main.
