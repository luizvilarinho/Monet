## 1. Chave privada do updater versionada num repositório público (b)

**Onde:** `~/.tauri/monet.key`, versionado desde `0f72a8b` (2026-05-20) e presente em `origin/develop` e em outras branches remotas; `package.json:14`.

```
$ git ls-files '~'      → ~/.tauri/monet.key, ~/.tauri/monet.key.pub
"tauri:build": "... Get-Content 'C:\\...\\Monet\\~\\.tauri\\monet.key' -Raw ..."
```

O `.gitignore` não cobre `~`, e o próprio script de build lê a chave de dentro do repositório. Isso já era o item C1 do `DOCS/features/fable_report.md` (2026-06-11), que constatou que o repositório era público. O item não entrou no backlog.

**Se ignorado:** quem quebrar a senha offline assina um instalador que o updater aceita. Além disso, cada instalação a mais encarece a rotação da chave, porque passa a exigir uma versão-ponte assinada com a chave velha. Sem usuários, hoje é o momento mais barato.

**Decisão do autor (2026-11-19):** a chave fica onde está por enquanto, sem rotação.

## 3. A keep sobrescreve a nota do dia com uma versão velha (b)

**Onde:** `src/components/KeepPanel/KeepPanel.tsx:286-296` e `:151-163`; `src-tauri/src/lib.rs:56-68`.

```
.onFocusChanged(({ payload: focused }) => { if (!focused) { notifyMainRef.current(); return } ... ed.view.focus() })
const updated: Note = { ...current, content: md, updatedAt: Date.now() }; storage.saveNote(updated)
```

A keep é `alwaysOnTop` e não se esconde quando perde o foco. Ela só recarrega a nota no `keep-shown`, que o Rust emite no toggle por atalho, ou no `calendar-note-updated`. A gravação que a main faz na nota do dia (`App.tsx:2584-2587`) não emite nada. Na mesma janela, o erro de gravação só vai para o console (`:159-161`): não há banner, e o próximo `keep-shown` recarrega do banco e apaga o texto que não foi gravado.

**Se ignorado:** quem digita na nota do dia pela main e depois volta à keep com um clique (não com Ctrl+K) e digita perde o que escreveu na main. Não há Ctrl+Z, porque a main recarrega o conteúdo fora do histórico.

## 4. Toggle com bloco de código (ou Mermaid) com linha em branco se corrompe ao gravar (a)

## 5. A migration v7 pode apagar a tabela que o Rust acabou de criar (instalação nova) (a) — confiança média

**Onde:** `src-tauri/src/lib.rs:1424-1428`; `src-tauri/src/documents.rs:220-222`, `:243-254` e `:383-386` (conexão em cache).

```
version: 7, description: "move_visibility_table_to_docdb", sql: "DROP TABLE IF EXISTS notebook_document_visibility;"
// do frontend (migrations do plugin rodam lazily, depois do open_doc_db).     // documents.rs:222
```

O Rust cria a tabela uma vez só, ao abrir a conexão que fica em cache. O `cleanup_stuck_indexing` espera apenas que o arquivo exista (`documents.rs:3260-3266`), não que as migrations terminem. Num banco novo, a v7 roda depois e apaga a tabela. Não dá para corrigir editando a v7: o sqlx recusa uma migration já aplicada que foi modificada.

**Se ignorado:** em toda instalação nova (todo usuário da Store), a visibilidade de documentos por caderno falha com "no such table" até o processo reiniciar, e o processo fica vivo na bandeja. Apagar um documento nesse estado remove os vetores e falha antes de limpar o `monet.db`.

## O que eu não consigo julgar

- **Repositório e senha (item 1):** se o repositório continua público e se a senha da chave resiste a força bruta. O `gh` não está instalado aqui, e o fable_report o via público em junho.
- **Ordem no banco novo (item 5):** se a ordem Rust → migrations acontece de fato numa instalação nova. O banco de dev é clone do de produção e nunca passa por esse caminho; só um teste com appData limpo responde.
- **Uso real dos itens 3 e 4:**
  - se você usa a keep aberta ao lado da main na nota do dia;
  - com que frequência há código ou Mermaid dentro de toggle.
- **Frequência do "�" (item 8):** depende de como o OpenRouter fatia os pacotes. Se nunca apareceu em respostas longas em português, o item desce.
- **Gatilho dos itens 6 e 9:** com que frequência o `SQLITE_BUSY` aparece no Stop (o busy_timeout é de 5 s) e se alguém instala uma atualização durante uma gravação.
- **Exfiltração (item 11):** se os modelos usados obedecem a uma injeção vinda de conteúdo web. Depende do modelo e das fontes.
- **Tamanho do chat no localStorage:** quanto o chat de uso real já ocupa, para saber a distância até a cota.
