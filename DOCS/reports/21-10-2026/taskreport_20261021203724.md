## Requirements
- **R1 — B1, two-way title sync.** Renaming a task (any surface: task modal, Tasks list, quick add, keep window) updates the text of its checklist item in the source note (`sourceNoteId`); only the source note is rewritten — pasted copies of the same task in other notes keep their text. The existing source→task sync keeps working; the new path must not loop with it (`seenSourceTitlesRef`), must preserve the `<TODOS> | ` prefix (`stripPipePrefix`) and must not wipe the item on an empty title.
- **R2 — A1, TODOS progress label.** The progress strip under the properties shows `Tasks 0/4` instead of `TODOS 0/4` (`TodosPanel.tsx` ~26); check whether any other place repeats the progress label (the sidebar shows only `N/N`).
- **R3 — A2, focus-mode width.** In focus mode the body uses the available width; today text, lists and task cards stop at the ~80ch measure while tables/images already go full width. Proposed decision: release the measure for every block only while focus is active (container class + `max-width: none`), keeping the measure outside focus. No per-note width setting in this task.
- **R4 — A3, shift+click on the ↗ icon.** Inside a TODOS note, shift+click on the ↗ icon of a checklist task card opens the task in `TaskEditorModal` without leaving the note; plain click on the icon keeps today's behavior (Tasks list + task body note). The modal must be available outside board views, must not swap the note behind it, and closing must return to the TODOS note unchanged. If the task has no body note, do not create one just for opening (proposed: properties-only modal with an explicit "add body note" action).
- **R5 — A4, card fields.** Inside TODOS notes the card shows every task field that has a value: project, TODOS, recurrence, checklist progress, do date, deadline, postponed count, importance and custom metadata; what does not fit in the single properties line is summarized as `+N more` (the `TaskCard` pattern, decided 2026-10-21). The same fields become editable inline — status (already), do date, deadline, importance, project, TODOS, recurrence and custom metadata — without opening the modal, reusing the controls/behavior of `TaskPropertiesBar`.
- **R6 — get_note chat tool.** A model-selected tool that looks up a note by title/name and returns metadata (title, notebook, type, archived; for TODOS, progress and tasks) plus a bounded body/excerpt, instead of RAG for direct lookups. It must respect notebooks with AI disabled (never return titles/content from them), handle ambiguous names (candidates or a clarification) and cap the returned size. RAG remains for open questions.
- **R7 — chat timings.** Each assistant answer shows a compact line with query rewrite, embedding, search, rerank, first word, tool rounds and total. Stage durations come from `rag_retrieve` (Rust) and from `useChat` instrumentation (first word, tool rounds, total); shown per response, not persisted in the conversation history.
- **R8 — notebook-chat note chip.** The Notebook chat shows a chip with the open note (and selection) that is going into the context; the user can remove it from the context; the sent message records which note it was written in.
- **R9 — archive pendings.** (a) `query_tasks` results mark a TODOS as archived; (b) `Archived:` appears in every RAG chunk header of an archived note, not only in the first chunk (Rust chunk header).
- **R10 — note-types/TODOS pendings.** (a) Weekly Review groups tasks by TODOS, with a "No TODOS" group at the end; (b) no leak of TODOS/source/linked-note titles or linked content from notebooks with AI disabled into `noteFileText`/chat context; (c) the keep-window echo in `saveTask` no longer overwrites newer fields (stale-write guard, e.g. `updated_at` in the UPSERT or reload before the toggle); (d) phase 5 (`task_group` removal) and (e) FTS5 plan B stay in the backlog.

## Edge Cases
- B1: source note open in the editor with unsaved changes; item with the `<TODOS> | ` prefix; empty title; the same task copied in other notes; multiple windows; title changed from modal/quick add/keep.
- A2: focus on/off and narrow windows; tables/images unaffected.
- A3: task without a body note; modal over the TODOS note itself; Esc/backdrop; the note behind must not change; task body in another notebook.
- A4: narrow card/overflow; popovers near the viewport edges; metadata defs removed; clicks that must not move the editor cursor; coexistence with the status menu.
- get_note: duplicate titles; archived notes/TODOS; very long notes; disabled notebook; ambiguous names.
- timings: RAG skipped (`continue`/short replies); rewrite/rerank failure; aborted response; tool rounds.
- chip: note/selection changing while composing; chat without an open note; disabled notebook.
- archive: tool results for archived TODOS; every chunk header of an archived note.
- note-types: empty Weekly Review; linked note in a disabled notebook; keep stale write; archived tasks.
