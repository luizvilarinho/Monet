# Explorer Report — Controle de margem lateral no leitor de EPUB

## Problema
Adicionar ao leitor de EPUB um controle de margem lateral (esquerda/direita) que permita ao usuário regular o comprimento da linha. Hoje existem apenas zoom de fonte e alternância 1↔2 colunas.

## Mapeamento do leitor de EPUB
- Componente React: `src/components/Reader/EpubReader.tsx` (1597 linhas) + `EpubReader.module.css`.
- Wrapper da lib epubjs (`@likecoin/epubjs`): `src/lib/epub.ts`. É a única fronteira — nada mais importa a lib direto.
- Não há código Rust/Tauri envolvido: o EPUB é renderizado dentro do WebView2 pelo epubjs.
- Container de leitura: `.pageArea` → `.viewerSurface` (largura máx. 860 px, `padding: 8px 20px`) → `.viewer` (flex:1, onde o iframe do epubjs é montado).

## Como o "zoom" (tamanho de fonte) está implementado hoje
- Estado React: `const [fontScale, setFontScale] = useState(() => clampFontScale(book.zoom))` (linha 224). Faixa 0.8–2.0, passo 0.1.
- Persistência: por livro, gravado na coluna `books.zoom` do SQLite via `storage.saveBook(updated)` (linhas 361–370, `flushPendingFont`). Debounce de 500 ms (`SAVE_DEBOUNCE_MS`). Flush no unmount. Reaproveita a coluna `zoom` do schema do PDF (mesma faixa, mesma convenção).
- Aplicação: `rendition.themes.fontSize(fontSizeCss(scale))` (linha 985). Força repaginação e reposiciona no CFI atual (`displayEpubAt`) — o epubjs joga o leitor para trás sem o reposicionamento.
- UI: grupo `.fontControls` na toolbar (linhas 1047–1067) — botões `−` e `+` ao redor de um rótulo `fontLabel` (mesmo padrão visual dos outros botões).

## Como a diagramação 1↔2 colunas está implementada hoje
- Estado React: `const [spreadMode, setSpreadMode] = useState<EpubSpreadMode>(() => localStorage.getItem(SPREAD_MODE_KEY) === 'none' ? 'none' : 'auto')` (linha 261).
- Persistência: **global**, em `localStorage` com a chave `monet:epub-reader-spread` (linhas 679–685). Não é por livro — comentário do código explica que é "preferência global de leitura, como o painel lateral".
- Aplicação: `setEpubSpread(rendition, mode)` em `lib/epub.ts` chama `rendition.spread(mode)`. Em seguida, o componente chama `displayEpubAt` no CFI atual (mesmo padrão da mudança de fonte).
- UI: grupo `.sideTabGroup` na toolbar (linhas 1089–1116) com dois botões toggle `1 col` / `2 col` (`highlightsToggle` + `highlightsToggleActive`).

## Viabilidade técnica de adicionar margem lateral
**Viável e simples.** A "margem" que o usuário sente como lateral não precisa mexer no CSS do livro: ela é o `padding` (ou a largura) do contêiner `.viewerSurface`. Reduzir/incrementar esse padding recolhe/expande o iframe do epubjs → a linha fica mais curta/comprida. Alternativa: usar `rendition.themes.override('padding-left', '...')` para injetar CSS no iframe — funciona, mas compete com a CSS do próprio EPUB (alguns livros definem margem própria e podem "vazar" para fora do corpo). A solução recomendada é controlar o padding externo, idêntica em espírito à `.viewerSurface` já existente.

Padrão recomendado para o controle:
- Estado: `useState` inicializado de `localStorage` (chave nova, ex.: `monet:epub-reader-margin`), com `MIN`/`MAX`/`STEP` em pixels (sugestão: 0–160 px, passo 16; 0 = sem margem extra, 160 = linha bem curta).
- Persistência: **global via localStorage**, igual à diagramação — comentário do código justifica tratar preferências de layout de leitura como globais, não por livro. Mantém simetria com `spreadMode` e evita criar nova coluna no schema do banco (a task é de "alteração mínima").
- Aplicação: `style={{ paddingLeft: marginPx, paddingRight: marginPx }}` em `.viewerSurface` (ou uma variável CSS `--epub-margin` referenciada no `EpubReader.module.css`). Sem `displayEpubAt` — o epubjs remedei via `ResizeObserver` já existente (linhas 586–606) e o `_stageSize` guard do epubjs torna o resize inofensivo.
- UI: novo grupo na toolbar, mesmo padrão `fontControls`/`sideTabGroup` — dois botões `−`/`+` ao redor do valor atual em px, com a chave `−` desabilitada no `MIN` e `+` no `MAX`. Aria-labels "Decrease margin" / "Increase margin".

## Persistência — padrão a seguir
- Zoom: por livro, em `book.zoom` no SQLite.
- Diagramação: global, em `localStorage` (`monet:epub-reader-spread`).
- **Margem deve ser global (localStorage)**, casando com a diagramação, que é a referência mais próxima (também ajusta layout de leitura, também é preferencia de conforto). Persistir por livro seria inconsistente e exigiria nova coluna no schema.

## Impactos e colaterais
- `.viewerSurface` já tem `padding: 8px 20px` e `max-width: 860px`. Aumentar a margem lateral pode reduzir demais a largura efetiva quando a janela é estreita (especialmente em 1 coluna com janela pequena). Mitigação: clamp inferior na largura efetiva, ou reduzir `max-width` proporcionalmente. Não é bloqueador — basta testar.
- Diagramação em 2 colunas: a margem lateral externa (a página toda) muda, mas o gap entre colunas é decidido pelo epubjs, não por nós. Comportamento esperado: margens maiores → cada coluna fica mais estreita. Considerar se o ideal é aplicar a margem como "insets externos" ou como "padding lateral de cada coluna" — decisão de UX a confirmar no plano.
- Repaginação: alterar a margem muda o tamanho do container → o `ResizeObserver` já dispara `resizeEpubRendition` + `displayEpubAt` no CFI atual (linhas 586–606). Não precisa de lógica nova: o mesmo caminho cobre o resize normal de janela.
- Grifos e seleção: ancoragem usa `pageAreaRef.current.getBoundingClientRect()` (linha 522), que não muda com padding interno da `.viewerSurface` — sem impacto.
- Reset entre livros: como é localStorage global, abre sempre com o último valor (igual à diagramação). Comportamento esperado.
- Zoom vs margem: ortogonais. Zoom altera fonte; margem altera largura do container. Sem interação adicional.

## Dificuldade
**Baixa.** Mudança contida em um componente, um módulo CSS e uma chave nova de localStorage. Sem refatoração, sem nova dependência, sem mudança de schema. O único ponto de cuidado é o clamp inferior da largura efetiva em janelas estreitas.

## Recomendações / ajustes de escopo
- Manter o escopo como descrito no Task Report — controle de margem lateral simples, na mesma toolbar, persistido como a diagramação.
- Aplicar a margem como padding lateral externo da `.viewerSurface` (não mexer no CSS injetado no iframe do EPUB). Isso evita conflito com a CSS do livro e mantém a decisão de UX centralizada no app.
- Valores sugeridos: 0–160 px, passo 16 px (10 níveis). Default 16 px (igual ao padding atual). Botão `−` desabilita no mínimo, `+` no máximo.
- Não persistir por livro — manter a consistência com a diagramação (global, localStorage).
- Não tratar dois botões separados "margem esquerda / margem direita" a menos que o Coordenador peça: o requisito fala em "margem lateral" (singular, comprimento de linha), e simetria esquerda/direita é o default esperado por leitores de EPUB. Manter escopo enxuto.
