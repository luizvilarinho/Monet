# Explorer Report — Mincer (VOLP dentro do Monet)

Task: `DOCS/reports/31-10-2026/taskreport_20261031005051.md` · Branch `feat/mincer`

## Problema
Portar o VOLP (`C:\Users\User\Documents\projetos\Minuta\minuta`, cerca de 3 mil linhas) para o Monet como 4º modo do menu principal, **Mincer**. O resultado de cada processamento precisa poder virar nota num caderno e virar conversa no Chat, dentro de uma seção nova "Mincer". É viável e não há impedimento técnico. O trabalho não é uma cópia: o VOLP não tem progresso, cancelamento, persistência nem processamento que continue fora da tela, e o Mincer precisa dessas quatro coisas.

**Dificuldade: Alta.** São seis frentes: módulo Rust novo, sidecars e empacotamento, jobs em background, tabela SQLite, UI nova em CSS Modules e integração com o Chat.

## 4. Persistência — recomendação

**Sim: criar um histórico de itens no SQLite.** Sem ele, o resultado se perde ao trocar de modo, e "enviar depois" não existe.

- Criar a tabela via `CREATE TABLE IF NOT EXISTS` em `open_doc_db` (é o Rust que escreve progresso e resultado) e acessá-la só por comandos Rust (`mincer_list`, `mincer_get`, `mincer_update`, `mincer_delete`). Não ler pelo plugin-sql. **Sem BEGIN/COMMIT manual.**
  ```
  mincer_items(id TEXT PK, kind TEXT  -- file|paste|record|youtube|web_summary|web_capture
    title TEXT, source TEXT          -- path/URL
    status TEXT                      -- queued|running|done|error|cancelled|interrupted
    stage TEXT, progress_current INT, progress_total INT, error TEXT,
    preset TEXT, extra_prompt TEXT, transcription_model TEXT, summary_model TEXT,
    transcript TEXT, summary TEXT,
    note_id TEXT, chat_folder_id TEXT, saved_path TEXT,
    created_at INT, updated_at INT)
  ```
- **Transcrição em coluna TEXT, não em arquivo.** Três horas de áudio dão ~200 KB de texto, o que o SQLite trata sem esforço, com escrita atômica e sem sincronizar arquivos. A lista lê só as colunas leves.
- **Os pedaços (mp3 e cache `.txt`) vão para `app_data_dir/mincer/<itemId>/`**, não para `%TEMP%`. Assim a retomada sobrevive a fechar o app, e a pasta é apagada no sucesso ou no "Delete". No boot, os itens em `running` passam a `interrupted`, com o botão Resume.
- **Chat:** o chat continua em localStorage (proposital). **Não gravar a transcrição na conversa.** A conversa leva no máximo o resumo, como 1ª mensagem do assistant, que tem poucos KB. A transcrição entra como **contexto efêmero no envio**, lida do SQLite (seção 6). Isso preserva o padrão validado do Reader e não estoura a cota de ~5 MB.

## 5. Processamento em background — recomendação

**O estado mora no Rust, com eventos e o SQLite como verdade. O React só observa.**
- Módulo `src-tauri/src/mincer/` (`mod.rs` com os comandos, `jobs.rs`, `transcribe.rs`, `youtube.rs`, `webpage.rs`, `record.rs`, `summarize.rs`, `sidecar.rs`, `db.rs`).
- `mincer_start(input) -> itemId` cria a linha e faz `tauri::async_runtime::spawn` do pipeline completo: download/extração → pedaços → transcrição → **resumo automático com o preset escolhido antes de começar**. O resumo roda no Rust e sem streaming; fazer streaming no componente quebraria ao desmontá-lo.
- O estado `MincerJobs(Mutex<Option<ActiveJob{item_id, cancel: watch/oneshot, child}>>)` comporta **um job por vez** no MVP. A gravação já é singleton.
- Eventos `mincer://progress {itemId, stage, current, total}`, `mincer://done` e `mincer://error`. A cada etapa e a cada pedaço, gravar `stage` e `progress` no banco.
- Cancelamento com `tokio::select!` entre a requisição e o sinal de cancelamento, mais `child.kill()` no ffmpeg e no yt-dlp. O yt-dlp com `--newline` permite parsear o `%`. Os pedaços já transcritos ficam no cache, então "Resume" continua de onde parou.
- Comandos de retomada e refazer: `mincer_resume(id)`, `mincer_cancel(id)` e `mincer_regenerate_summary(id, preset, model, extra)`, este último também como job.
- No front, `useMincerJobs` montado **no App** (não no componente Mincer): escuta os eventos, mantém o item ativo e alimenta um **indicador no botão Mincer da Toolbar** quando há job rodando. O componente `Mincer` relê `mincer_list` ao montar.
- O X só esconde a janela, então o job continua com a janela escondida. Opcional: notificação (o plugin notification já existe) ao terminar.

## 7. Riscos

1. **Gravação:** o WAV em float32 ocupa ~2 GB/h de disco. Mitigar gravando em 16-bit ou reamostrando (ou aceitar no MVP e documentar). Microfone negado (privacidade do Windows) ou ausência de saída: tratar como `(false,false)` e responder com mensagem clara. Os erros das threads precisam subir para a UI, não ficar no `eprintln`.
2. **YouTube:** o yt-dlp envelhece (pode já estar quebrado) e a Store pode recusar o app. Planejar uma flag de build.
3. **Tamanho do instalador e do update**, além da licença GPL do ffmpeg.
4. **Concorrência no chat:** a janela assistant oculta reconcilia o localStorage, então seguir à risca o padrão `folderId` atômico.
5. **Duas conexões no `monet.db`:** o Rust grava progresso com frequência. Usar escritas curtas, nunca segurar o lock do `DocDb` durante I/O de rede.
6. **Custo e contexto:** 60k caracteres de transcrição a cada mensagem do chat. O orçamento precisa ser configurável no código.
7. **PRD:** o "resumir tudo automaticamente" encosta na não-meta. Fica mitigado porque nada vai para caderno sem clique.

## 8. Escopo recomendado (MVP)
Modo Mincer; módulo Rust portado com job em background, progresso, cancelamento e retomada persistente; sidecars resolvidos corretamente; entradas File (áudio, vídeo, txt, md), Paste, Record, YouTube, Web summary e Web capture (sem resumo); presets com resumo automático e Regenerate; histórico no SQLite; salvar `.md` em pasta; enviar para caderno; enviar para Chat com o grupo Mincer e contexto efêmero com orçamento; indicador na Toolbar.

**Remover do VOLP (dead code):** `settings.rs`, `Settings.tsx`, `useOpenRouter`/`fetch_models`, plugins store/dialog/fs, Tailwind, `TranscribeState` em memória e `has_resume_state` (viram status no banco), fallbacks CapCut/meetily, o `multipart` do reqwest.

Estimativa grosseira: ~1,5–2 mil linhas novas (Rust ~900, React/CSS ~1000), mais os ajustes em `useChat`, `ChatSidebar`, `ChatPanel`, `Toolbar`, `App` e `lib.rs`.
