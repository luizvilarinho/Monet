# Plano — Mincer (VOLP dentro do Monet)

Task: `DOCS/reports/31-10-2026/taskreport_20261031005051.md` · Explorer: `DOCS/reports/31-10-2026/explorerreport_20261031005653.md` · Branch `feat/mincer`

## Escopo
Novo modo **Mincer** (4º item do menu: Notebook, Chat, Library, Mincer) que processa grandes volumes. Tem seis entradas: arquivo (áudio, vídeo, `.txt`/`.md`), colar texto, gravação (áudio do sistema + microfone), YouTube, página web com resumo e página web só com captura do texto.

O processamento roda como **job no Rust** (módulo `src-tauri/src/mincer/`), com eventos de progresso, cancelamento e retomada. Os pedaços ficam em cache em `appData/mincer/<id>/`. O resumo é automático, com preset, e pode ser refeito com Regenerate.

**O Mincer nunca interrompe o uso do Monet.** Ele funciona assim:
- Há uma **fila FIFO persistida no SQLite** (status `queued`, ordem por `queued_at`). O usuário enfileira quantos itens quiser, a qualquer momento, e um worker no Rust processa um de cada vez.
- Não há modal bloqueante nem botão travado por job ativo.
- Todo trabalho pesado fica fora da thread do webview: rede, ffmpeg/yt-dlp com prioridade abaixo do normal, e base64 e leitura de arquivo em `spawn_blocking`.
- As escritas no `monet.db` são curtas.

Ao terminar cada item, com sucesso ou erro, o Rust dispara um **toast nativo do Windows** (`tauri-plugin-notification`, que já está instalado), que funciona com a janela escondida na bandeja. Não há toast quando o usuário cancela.

O histórico fica na tabela `mincer_items` (SQLite, acessada só por comandos Rust). Cada item tem estas saídas:
- salvar `.md` com front-matter numa pasta escolhida;
- Send to notebook, que reaproveita o `SaveToNoteModal`;
- Send to Chat: grupo "Mincer" no Chat, uma pasta por item, com o resumo como 1ª mensagem e a transcrição como `ephemeralContext` lido do SQLite, com limite de tamanho.

Há também um indicador de job na Toolbar. Os modelos ficam numa seção nova "Mincer" do Settings existente. O plano também cobre:
- os sidecars ffmpeg e yt-dlp: fora do git, com script de cópia e declarados em `externalBin`;
- o resolvedor de sidecar corrigido;
- a remoção de `language:"pt"`;
- matar os processos filhos ao cancelar e ao sair;
- a spec `DOCS/specs/mincer.md` e o registro no menu e no backlog.

Fora do escopo (fase 2): RAG das transcrições, Calendar, legendas do YouTube, ffmpeg mínimo, atualizador do yt-dlp, flag de build para o YouTube e mudanças no `build-msix.ps1` (o script não existe no disco; só entra no backlog).

## Contratos (referência única para todas as etapas)

### Tabela `mincer_items` (criada em `open_doc_db`, `src-tauri/src/documents.rs`)
```sql
CREATE TABLE IF NOT EXISTS mincer_items (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL,                 -- file | paste | record | youtube | web_summary | web_capture
  title TEXT NOT NULL DEFAULT '',
  source TEXT,                        -- caminho do arquivo ou URL; NULL em paste/record
  status TEXT NOT NULL,               -- queued | running | done | error | cancelled | interrupted
  stage TEXT,                         -- mixing | downloading | extracting | splitting | transcribing | fetching | summarizing
  progress_current INTEGER NOT NULL DEFAULT 0,
  progress_total INTEGER NOT NULL DEFAULT 0,
  error TEXT,
  preset TEXT,                        -- id do preset (meeting|class|news|scientific), só para exibição
  summary_prompt TEXT,                -- system prompt já resolvido (preset + instruções extras)
  transcription_model TEXT,
  summary_model TEXT,
  transcript TEXT,                    -- transcrição ou texto de entrada/capturado
  summary TEXT,
  queued_at INTEGER,                  -- posição na fila (FIFO); gravado ao enfileirar
  force_summary INTEGER NOT NULL DEFAULT 0, -- 1 = refazer o resumo (Regenerate) na próxima execução
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_mincer_items_created ON mincer_items(created_at DESC);
CREATE INDEX IF NOT EXISTS idx_mincer_items_queue ON mincer_items(status, queued_at);
```
**A fila é o próprio banco.** O próximo item é `SELECT id, force_summary FROM mincer_items WHERE status='queued' ORDER BY queued_at ASC LIMIT 1`, então a fila sobrevive a fechar o app sem estrutura em memória além do job ativo.
Sem BEGIN/COMMIT manual. Todas as escritas são curtas, via `documents::with_doc_db`, e o lock do `DocDb` nunca fica preso durante I/O de rede ou de processo.

### Pasta de trabalho de um item: `app_data_dir()/mincer/<id>/`
| Arquivo | Papel |
|---|---|
| `loopback.wav`, `mic.wav` | Gravação (só no kind `record`, até a mixagem) |
| `options.json` | Só em `app_data_dir()/mincer/recording/`, durante a gravação |
| `yt_audio.<ext>` + `yt_audio.done` | Download do YouTube concluído |
| `audio.mp3` | Áudio extraído/mixado (mono, 16 kHz, 64 kbps); gravado como `audio.tmp.mp3` e renomeado no fim |
| `chunk_NNN.mp3` + `chunks.done` | Pedaços prontos (o marcador só é escrito depois do split terminar) |
| `chunk_NNN.txt` | Cache da transcrição de cada pedaço (retomada) |

A pasta é apagada quando o item termina `done` e quando o item é deletado. A gravação em curso usa `app_data_dir()/mincer/recording/`.

### Eventos
| Evento | Payload (camelCase) | Quando |
|---|---|---|
| `mincer://progress` | `{ itemId, stage, current, total }` | início de cada etapa, a cada pedaço transcrito, a cada % inteiro do download |
| `mincer://done` | `{ itemId }` | job terminou com sucesso |
| `mincer://error` | `{ itemId, message, cancelled: bool }` | job falhou ou foi cancelado |
| `mincer://record` | `{ active: bool }` | gravação iniciou/parou |

O 1º `mincer://progress` de um job marca o job como ativo no front. Não existe evento "started". Cancelar um item **enfileirado** também emite `mincer://error {cancelled:true}`, para as listas se atualizarem.

### Etapa 8 — Worker da fila (requisito do Coordenador: nunca bloquear o Monet; toast ao terminar): pipeline, enfileirar/cancelar, notificação, startup e encerramento
- Status: PENDENTE
- Descrição: criar `src-tauri/src/mincer/jobs.rs`. Modelo: **fila FIFO no banco + um worker**. Todo pedido (start, resume, regenerate, fim de gravação) só **enfileira** e chama `start_next`, que nunca bloqueia: se já há job ativo, não faz nada, e o item espera a vez.
  1. `pub(crate) fn start_next(app: &AppHandle)`:
     - trava `MincerJobs`; se houver job ativo, retorna;
     - `db::next_queued(app)`; se não houver item, retorna;
     - cria `watch::channel(false)` e o `child_pid`, grava o `ActiveJob { item_id, … }` (ainda com o lock, para duas chamadas simultâneas não pegarem o mesmo item) e solta o lock;
     - `db::set_running(app, &id)`, depois `tauri::async_runtime::spawn(run_and_finish(app.clone(), ctx, force_summary))`.
  2. `async fn run_and_finish(app, ctx, force_summary)`: chama `run_item(&ctx, force_summary)` e, ao terminar:
     - `Ok` → `set_finished("done", None)`, `remove_dir_all(item_dir)` (ignorando erro), emite `done` e chama `notify(&app, &id, Ok(()))`;
     - `Cancelled` → se o status no banco ainda é `running` (o encerramento pode tê-lo devolvido à fila), `set_finished("cancelled", Some("Cancelled."))` e emite `error {cancelled:true}`. Mantém a pasta e **não notifica**;
     - `Failed(m)` → `set_finished("error", Some(&m))`, emite `error {cancelled:false}` e chama `notify(&app, &id, Err(&m))`. Mantém a pasta;
     - por fim limpa `MincerJobs` (só se o `item_id` ainda for o deste job) e chama `start_next(&app)` para o próximo da fila.
  3. `fn notify(app, id, result: Result<(), &str>)`: lê o título e o kind (`db::get_item`; falha vira `"item"`) e mostra o toast conforme a seção Contratos › Notificações (`tauri_plugin_notification::NotificationExt`). Erro do plugin só com `eprintln!`.
  4. `pub(crate) fn enqueue_and_start(app, id, force_summary: bool) -> Result<(), String>`: `db::enqueue(app, id, force_summary)`, depois `start_next(app)`.
  5. `async fn run_item(ctx: &JobCtx, force_summary: bool) -> Result<(), JobError>`:
     - carrega o item com `db::get_item` (ausente vira `Failed("Item not found.")`);
     - a chave é `crate::read_key(&ctx.app, "openrouter_key")`, exigida só quando há chamada ao OpenRouter; ausente vira `Failed("OPENROUTER_KEY_MISSING")`.
     - **Texto** (quando `transcript` está vazio):
       - `paste` / `file` de texto: o texto já foi gravado no start; se estiver vazio, `Failed("The text is empty.")`;
       - `web_summary` / `web_capture`: `ctx.progress("fetching",0,0)` e `webpage::fetch_article(source)`; se vier título, `db::set_title`; depois `db::set_transcript`;
       - `youtube`:
         - resolve o `yt-dlp` e o `item_dir`;
         - se não há `yt_audio.done`, chama `fetch_title` e `db::set_title` quando houver título;
         - `download_audio`, depois `transcribe_media(Some(audio), …)`, depois `set_transcript`;
       - `file` de mídia: `transcribe_media(Some(source), …)`, depois `set_transcript`;
       - `record`: se não há `audio.mp3` nem `chunks.done`, `record::mix`; depois `transcribe_media(None, …)` e `set_transcript`.

       O modelo de transcrição vem de `item.transcription_model` (vazio vira `Failed("Choose a transcription model in Settings.")`).
     - **Resumo**: se `kind != "web_capture"` e (`force_summary` ou `summary` vazio):
       - `ctx.progress("summarizing",0,0)`;
       - `summarize::summarize(ctx, key, summary_model, summary_prompt, transcript)`;
       - `db::set_summary`.

       `summary_model`/`summary_prompt` vazios viram `Failed("Choose a summary model in Settings.")`.
  6. `pub(crate) fn cancel(app, id) -> Result<(), String>`:
     - se o `ActiveJob.item_id == id`, `cancel.send(true)`; o `run_and_finish` grava `cancelled` e o processo filho morre pelo `kill_on_drop`;
     - senão, se `db::get_status == "queued"`, o item sai da fila com `set_finished(id, "cancelled", Some("Removed from queue."))` e emite `error {itemId, message, cancelled:true}`;
     - senão, nada.
  7. `pub(crate) fn active_item_id(app) -> Option<String>`.
  8. `pub async fn on_startup(app: AppHandle)`:
     - `db::mark_running_interrupted(&app, "Monet was closed while this item was processing.")`. Isso cobre um crash: o item **não** é retomado sozinho, para não entrar em loop num item que derruba o app; fica com Resume;
     - se `mincer_root/recording/` tem WAV utilizável, `record::finalize_into_item(&app, &[])` (gravação recuperada, entra na fila), com o erro só em `eprintln!`;
     - apaga as pastas em `mincer_root` (exceto `recording`) cujo nome não está em `db::item_ids`;
     - por fim `start_next(&app)`: os itens `queued` de antes do fechamento voltam a rodar sozinhos, em ordem.
  9. `pub fn shutdown(app: &AppHandle)` (Quit limpo):
     - (a) se há gravação: `take` do handle, `record::stop_handle`, depois `record::finalize_into_item(app, &errors)`. A gravação vai para a fila e é transcrita no próximo boot;
     - (b) se há job ativo: `db::requeue_front(app, &id)` **antes** de cancelar (volta à frente da fila e retoma do cache no próximo boot), depois `cancel.send(true)` e `kill_tree(pid)` quando houver pid.
  10. **Regras de não-bloqueio** (valem para o módulo inteiro):
      - nenhuma chamada de rede, de processo ou de arquivo grande dentro de `with_doc_db`;
      - o lock de `MincerJobs` só é segurado para ler ou trocar o `Option`;
      - o progresso do download só vai ao banco quando o % inteiro muda;
      - os comandos Tauri retornam assim que o item é enfileirado.
  11. `src-tauri/src/lib.rs`:

## Notas ao Orquestrador (limitações aceitas, decisões do planner)
- **Modelos no Settings, não na tela do Mincer.** É o padrão pedido (o mesmo do "Retrieval model"). O de transcrição é um `<select>` carregado do OpenRouter, porque não há id seguro para usar como default. O de resumo é texto livre e, vazio, usa o modelo do Chat. Sem modelo de transcrição, os modos de áudio ficam bloqueados com o botão "Open Settings".
- **Fila FIFO no banco (requisito do Coordenador).** Start, Resume, Regenerate e o fim da gravação só enfileiram. Um worker processa um item por vez, e a ordem vem de `queued_at`. Não existe estado de fila em memória além do job ativo, então a fila sobrevive a fechar o app.
  - Num crash, o item que estava rodando vira `interrupted` e não é retomado sozinho, para evitar loop.
  - No Quit limpo, o item ativo volta à frente da fila.
- **Toast ao terminar (requisito do Coordenador).** Disparado do Rust; o plugin já existe. O clique no toast **não** abre o item, porque o plugin não tem callback de clique no Windows desktop. A limitação está registrada na spec e no backlog.
- **Encerramento.** O X só esconde a janela, então o job continua. No Quit, a gravação em curso é salva como item `interrupted` e o ffmpeg/yt-dlp é morto via `taskkill /T` pelo pid guardado. Num crash, a gravação é recuperada no boot seguinte.
- **Colunas `note_id`, `chat_folder_id` e `saved_path` ficaram fora** do schema proposto pelo explorer. O vínculo com o Chat fica em localStorage, como Library e Notebook, e nenhuma tela precisava das outras duas.
- **Editar a transcrição** (o textarea do VOLP) não foi portado. O Chat e a nota recebem o texto como veio, e o item pode ser renomeado.
- **Mixagem e retomada da gravação.** A mixagem roda dentro do job (cancelável). Os WAVs ficam na pasta do item até virar `audio.mp3`, então o Resume funciona.
- **`chrono` adicionado** para a data local do título da gravação, do nome da pasta do Save .md e do front-matter, em vez de mandar datas do front.
- Custo: até ~60k chars de transcrição vão em cada mensagem do chat do Mincer (orçamento em `mincerContext.ts`). O RAG das transcrições fica para a fase 2.
