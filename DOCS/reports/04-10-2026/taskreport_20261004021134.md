# Task: Save web sources, mover notas/cadernos e caderno no Calendar

## Objective
Quatro ajustes no Monet: renomear a tool de chat "Web research" para "Save web sources" (evitando confusão com a tool "web search" já existente), permitir mover uma nota para outro caderno via ícone + modal, permitir mover um caderno inteiro para dentro de outro (o caderno de origem vira um subject no destino) e exibir o nome do caderno acima das notas alteradas no dia dentro do Calendar.

## Context
- Monet: app desktop Tauri 2 + React 18 + TypeScript + CSS Modules; dados em SQLite via camada de abstração `src/storage/` (`index.ts`, `tauri.ts`, `browser.ts`); vetores do RAG em banco separado (`monet-vec.db`).
- Hierarquia de dados: caderno → subject (agrupador interno do caderno) → nota.
- Áreas de UI afetadas: painel de chat (seletor de tools, onde convivem "Web research" e "web search"); lista de notas (ícones ao lado do nome da nota); lista de cadernos (ícones ao lado do nome do caderno); Calendar (área de notas alteradas naquele dia).
- Especificação de referência: `DOCS/specs/systemSpecification.md`.

## Requirements
- Renomear o rótulo "Web research" para "Save web sources" em todos os pontos visíveis ao usuário na parte de chat (seletor de tools, tooltips, mensagens de status), sem alterar a tool "web search" e sem mudar o comportamento da tool renomeada.
- Mover nota para outro caderno: novo ícone ao lado do nome da nota, junto aos ícones existentes; ao clicar, abre modal para escolher o caderno destino; ao confirmar, a nota passa a pertencer ao caderno escolhido.
- Mover caderno inteiro: novo ícone ao lado do nome do caderno, junto aos ícones existentes; ao clicar, abre modal para escolher o caderno destino; ao confirmar: (1) é criado no destino um subject com o nome do caderno de origem, (2) todas as notas da origem passam a pertencer a esse subject, (3) o caderno de origem deixa de existir como caderno.
- Calendar: na área de notas alteradas no dia, incluir o nome do caderno acima do título da nota (apenas isso, sem outros elementos visuais novos).

## Constraints
- Seguir a stack existente: React 18 + TypeScript, CSS Modules com variáveis CSS; sem framework/biblioteca nova.
- Toda persistência pela camada `src/storage/` — sem SQL direto no frontend; manter as implementações (tauri/browser) coerentes quando a operação existir nas duas.
- IDs das notas não mudam ao serem movidas (preserva embeddings do RAG e vínculos existentes).
- Reutilizar os padrões visuais dos ícones e modais já existentes no app.
- UI em português, exceto o rótulo "Save web sources", definido pelo Coordenador em inglês.

## Edge Cases
- Mover caderno para si mesmo: excluir o caderno de origem da lista de destinos do modal.
- [Pendente ao Coordenador] Caderno de origem contém subjects: achatar todas as notas dentro do subject único criado no destino (leitura literal do pedido) ou reproduzir os subjects de origem no destino?
- [Pendente ao Coordenador] Nota movida individualmente está dentro de um subject: presume-se que ela vai para a raiz do caderno destino (sem subject). Confirmar.
- [Pendente ao Coordenador] Destino já possui subject com o mesmo nome do caderno de origem: mesclar as notas no subject existente, criar duplicado ou renomear?
- Caderno de origem vazio: comportamento uniforme presumido — cria subject vazio no destino.
- Calendar: exibir o caderno atual da nota (se a nota foi movida depois, mostrar o caderno novo).
- Renomeação da tool: varrer a UI para não restar nenhuma ocorrência visível de "Web research" (tooltip, mensagem, placeholder).
