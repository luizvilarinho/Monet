## Tarefa 1 — Botão PREVIEW (ocultar slash commands)

**Comportamento:** Botão "preview" ao lado do "export .md" na `Toolbar.tsx`. Ao clicar, alterna um estado `previewMode` que oculta visualmente as linhas de slash commands (`/comando...`) dentro do editor. Continua editável — apenas esconde os parágrafos que começam com `/`. Clicar novamente restaura a visualização.

**Implementação:**
1. **`Toolbar.tsx`**: Adicionar prop `previewMode: boolean` e `onTogglePreview: () => void`. Adicionar botão "preview" ao lado de "export .md" (mesmo grupo `noteActions`), com estilo ativo quando `previewMode === true`.
2. **`App.tsx`**: Adicionar estado `const [previewMode, setPreviewMode] = useState(false)`. Passar para `Toolbar` e para `Editor`.
3. **`Editor.tsx`**: Adicionar prop `previewMode?: boolean`. Criar um plugin ProseMirror (ou extensão TipTap simples) que adiciona `Decoration` do tipo `hidden` (CSS `display: none`) em parágrafos que casam com `isPotentialCommandLine` (`/^\s*\//`). O plugin reage às mudanças (`AppendTxn` / `DocChanged`) e ao toggle do `previewMode`. Quando `previewMode === false`, o plugin não adiciona decorações.
4. **CSS (`Editor.module.css`)**: Adicionar regra `.proseEditor :global(.monetCmdHidden) { display: none; }` como fallback caso o Decoration `hidden` não funcione — preferimos usar Decoration com `class: 'monetCmdHidden'` para simplicidade e robustez.

**Arquivos:**
- `src/components/Toolbar/Toolbar.tsx` — adicionar botão + props
- `src/App.tsx` — estado `previewMode` + wiring
- `src/components/Editor/Editor.tsx` — prop `previewMode` + plugin de decoração
- `src/components/Editor/extensions.ts` — opcionalmente registrar o plugin de preview aqui
- `src/components/Editor/Editor.module.css` — classe `.monetCmdHidden`

## Tarefa 5 — Hierarquia de tasks (aninhar com Tab)

**Comportamento:** Hoje o `TaskItem` está configurado com `nested: false` em `extensions.ts:112`. Isso impede criar subtasks. Ao mudar para `nested: true`, o TipTap passa a permitir que um `taskItem` contenha outro `taskList` como filho, e o comportamento padrão de Tab/Shift+Tab aumenta/diminui o recuo.

**Implementação:**
1. **`extensions.ts:112`**: Trocar `TaskItem.configure({ nested: false })` → `TaskItem.configure({ nested: true })`.
2. **CSS (`Editor.module.css`)**: Adicionar regras para indentação visual de tasks aninhadas:
   ```css
   .proseEditor :global(ul[data-type="taskList"] ul[data-type="taskList"]) {
     padding-left: 1.8em;
     margin: 0.1em 0;
   }
   ```
3. **Verificação:** Confirmar que o `tiptap-markdown` serializa/desserializa corretamente sublists aninhadas (deve gerar `  - [ ] subtask` com indentação). Testar round-trip markdown ↔ editor.
4. **Atenção:** O drag handle de tasks em `CommandExtension.ts` (`computeTaskDropTarget`) assume estrutura plana — verificar se ainda funciona com tasks aninhadas e ajustar se necessário (provavelmente não quebra, pois itera por `depth`).

**Arquivos:**
- `src/components/Editor/extensions.ts` — `nested: true`
- `src/components/Editor/Editor.module.css` — indentação visual de subtasks
- `src/components/Editor/CommandExtension.ts` — revisar `computeTaskDropTarget` (validação)

## Tarefa 6 — Menu de contexto (botão direito) com formatação

**Comportamento:** Ao clicar com o botão direito em qualquer lugar do editor, aparece um menu flutuante na posição do clique com as opções de formatação (as mesmas do `FORMATTING_GROUPS` da `FormattingToolbar`: H1/H2/H3, Bold/Italic, listas, toggle, quote, code, codeBlock, table, image, link, hr). Ao selecionar uma opção, é criada uma NOVA linha (na posição do cursor ou abaixo da linha atual) já com a formatação escolhida. Manter também o item "inserir link de nota" que já existe hoje.

**Implementação:**
1. **`Editor.tsx`**: Adicionar handler `handleContextMenu` no `EditorContent` (ou via `editorProps.handleDOMEvents`). Prevenir o menu padrão (`e.preventDefault()`), capturar a posição no documento via `view.posAtCoords({ left: e.clientX, top: e.clientY })`, e exibir um menu customizado (componente React) na posição do clique.
2. **Novo componente `ContextMenu.tsx`** (em `src/components/Editor/`): Menu flutuante reutilizável. Renderiza grupos de botões (reaproveitar `ButtonDef` e `runAction` da `FormattingToolbar`, extraindo para um módulo compartilhado `formattingActions.ts`). Diferença: ao acionar uma ação a partir do menu de contexto, primeiro insere uma nova linha vazia (Enter) e depois aplica a formatação, OU usa comandos ProseMirror para criar o node formatado diretamente na posição do clique.
3. **Refatoração:** Extrair `FORMATTING_GROUPS`, `runAction`, `isActive` e `FormatId` de `FormattingToolbar.tsx` para `src/components/Editor/formattingActions.ts`, para reuso entre BubbleMenu e ContextMenu.
4. **Lógica de "nova linha formatada":** Para cada ação, criar um node do tipo apropriado na posição do cursor:
   - `h1/h2/h3` → inserir parágrafo vazio e aplicar `toggleHeading`
   - `ul/ol/todo` → inserir lista e primeiro item
   - `toggle` → inserir `toggleBlock` com título vazio
   - `blockquote` → inserir blockquote
   - `codeBlock` → inserir codeBlock
   - `table` → inserir tabela 3×3
   - `hr` → inserir divisor
   - `code/link/bold/italic/image` → nestes casos (inline marks), inserir parágrafo novo e aplicar mark/ação
5. **CSS:** Adicionar `ContextMenu.module.css` com estilo de menu flutuante (fundo escuro, bordas, sombra, posicionamento absoluto).

**Arquivos:**
- `src/components/Editor/formattingActions.ts` — NOVO: extrair ações de formatação compartilhadas
- `src/components/Editor/FormattingToolbar.tsx` — refatorar para importar de `formattingActions`
- `src/components/Editor/ContextMenu.tsx` — NOVO: componente de menu de contexto
- `src/components/Editor/ContextMenu.module.css` — NOVO: estilos do menu
- `src/components/Editor/Editor.tsx` — handler de contextmenu + render do ContextMenu
- `src/components/Editor/Editor.module.css` — ajustes se necessário
